selectOption()

Beginner 5 min read

Prerequisites: Actions overview, getByLabel()

What is selectOption()?

locator.selectOption(
  value: string | string[] | { value?: string, label?: string, index?: number }
)

selectOption() chooses one or more options in a native <select> dropdown, in a single call — no need to click to open it, hover an option, and click again, the way a raw simulation of the interaction would require.

Why it's important

Native <select> elements render their own OS-level dropdown UI in most browsers, which isn't part of the regular DOM and can't be interacted with via ordinary clicks the way custom dropdowns can. selectOption() sidesteps this entirely by operating on the underlying <select> element's value directly, which is both simpler and more reliable than trying to click through a native OS dropdown.

Selecting by value, label, or index

// By the option's value attribute
await page.getByLabel('Country').selectOption('IN');

// By the option's visible label text
await page.getByLabel('Country').selectOption({ label: 'India' });

// By position (least readable — avoid unless genuinely necessary)
await page.getByLabel('Country').selectOption({ index: 2 });

Selecting by value or label is almost always preferable to index — index-based selection breaks silently if the option order changes for any reason unrelated to the feature under test.

Basic Example

await page.getByLabel('Shipping method').selectOption('express');

Detailed Example — Multi-Select

// A multi-select <select multiple> — pass an array to select several options at once
await page.getByLabel('Skills').selectOption(['playwright', 'typescript', 'ci-cd']);

await expect(page.getByLabel('Skills')).toHaveValues(['playwright', 'typescript', 'ci-cd']);

Real-World Example — Dependent Dropdowns

test('selecting a country populates the state dropdown', async ({ page }) => {
  await page.goto('/shipping-address');

  await page.getByLabel('Country').selectOption({ label: 'United States' });

  // The state dropdown's options are populated dynamically after country changes
  const stateDropdown = page.getByLabel('State');
  await expect(stateDropdown.getByRole('option', { name: 'California' })).toBeAttached();

  await stateDropdown.selectOption({ label: 'California' });
  await expect(stateDropdown).toHaveValue('CA');
});

Note the wait implied by toBeAttached() before selecting — since the state dropdown's options are populated asynchronously after the country change, this confirms they've actually loaded before attempting the second selection, rather than assuming they're there instantly.

❌ Fragile vs. ✅ Recommended

// ❌ Position-based — breaks if the option order changes
await page.getByLabel('Country').selectOption({ index: 5 });

// ✅ Meaning-based — stable regardless of order
await page.getByLabel('Country').selectOption({ label: 'India' });

Common Mistakes

  • Trying to click a native <select>'s options directly — the dropdown's open-state UI is rendered by the OS/browser outside the normal DOM in many cases, so clicking "into" it the way you'd click a custom dropdown often doesn't work reliably; selectOption() exists specifically to avoid this problem.
  • Using selectOption() on a custom, non-native dropdown component (a styled <div>-based combobox) — this only works on real <select> elements; custom dropdowns need click() to open plus a subsequent click() or press() on the option (see press() for arrow-key-driven examples).
  • Selecting by index without a comment explaining why — makes the test harder to maintain since the intended option isn't visible from the code itself.

Edge Cases

  • Disabled options within an enabled select — selectOption() will throw if targeting a disabled <option>, correctly reflecting that a real user couldn't select it either.
  • Dynamically populated selects (options loaded via an API call after the page renders) — as in the dependent-dropdown example, ensure the options actually exist before selecting; Playwright's auto-waiting covers the select element itself being ready, but doesn't know to wait for a specific option's asynchronous arrival.

Debugging

If selectOption() throws "option not found," verify the exact value attribute or label text via DevTools — a common surprise is a select's visible label text differing slightly from what's expected (extra whitespace, different casing) even when the value attribute would have matched.

Best Practices

  • Prefer value or label over index — reserve index-based selection for cases with no stable value/label to key off, such as auto-generated options.
  • For custom (non-native) dropdown components, don't reach for selectOption() at all — use click()/press() matching how the component actually behaves.

Practice Exercise

Given a native multi-select with options "Red," "Green," "Blue," "Yellow," write a test that selects "Green" and "Yellow" only, and asserts "Red" and "Blue" remain unselected.

Summary

selectOption() operates on native <select> elements by value, label, or index, sidestepping the unreliable process of clicking through a browser-rendered dropdown. It doesn't work on custom-built dropdown components, which need ordinary click/keyboard interaction instead.

Interview Questions

Why can't you just click() a native <select> dropdown's option the way you would with a custom dropdown component?▾
Many browsers render a native select's open dropdown as an OS-level UI element outside the regular web page DOM, so it isn't reliably clickable through ordinary DOM-based automation. selectOption() avoids this entirely by setting the select element's value directly and dispatching the appropriate change event, which is both more reliable and closer to what actually needs to be verified — the resulting value, not the visual act of opening a dropdown.
Why can't you just click() a native <select>'s open option list the way you would a custom dropdown?▾
Many browsers render the open state as an OS-level UI outside the normal page DOM, so it isn't reliably clickable through DOM automation.
What are the three ways to select an option with selectOption()?▾
By value, by label, or by index — value and label are preferred since they're more meaningful and stable than position.
Does selectOption() work on a custom, non-native combobox component?▾
No — it only works on real <select> elements; custom dropdowns need a click-then-click pattern instead.
What happens if you try to select a disabled <option>?▾
selectOption() throws, correctly reflecting that a real user couldn't select it either.
