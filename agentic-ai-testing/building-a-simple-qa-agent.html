Building a Simple QA Agent

Beginner 11 min read

Prerequisites: Capturing Agent Results

What is this?

Every piece from this chapter's seven previous pages, assembled into one complete, genuinely working file — nothing new introduced here, just the full picture in one place, the way it would actually exist in a real project.

The Complete agent.py

import os
from anthropic import Anthropic
from dotenv import load_dotenv
from tools import click_element, fill_field, get_page_text, get_current_url

load_dotenv()

TOOL_DEFINITIONS = [
    {"name": "click_element",
     "description": "Clicks a visible element identified by its accessible role and name.",
     "input_schema": {"type": "object",
        "properties": {"role": {"type": "string"}, "name": {"type": "string"}},
        "required": ["role", "name"]}},
    {"name": "fill_field",
     "description": "Types text into a visible, editable form field identified by its label.",
     "input_schema": {"type": "object",
        "properties": {"label": {"type": "string"}, "value": {"type": "string"}},
        "required": ["label", "value"]}},
    {"name": "get_page_text",
     "description": "Returns the visible text content of the current page.",
     "input_schema": {"type": "object", "properties": {}}},
]

MAX_STEPS = 15

class QAAgent:
    def __init__(self, api_key):
        self.client = Anthropic(api_key=api_key)
        self.model = "claude-sonnet-4-6"
        self.objective = None
        self.instructions = """You are a QA testing agent for ShopEasy.
Verify features work correctly and report genuine issues clearly.
Never submit a real order or modify real customer data.
When something is ambiguous, note it explicitly rather than
silently guessing. State clearly what you verified and what you
did NOT verify. Respond with "TASK COMPLETE" followed by a
summary once the objective is genuinely achieved."""

    def set_objective(self, objective):
        self.objective = objective

    def execute_tool(self, tool_name, tool_input, page):
        if tool_name == "click_element":
            return click_element(page, **tool_input)
        elif tool_name == "fill_field":
            return fill_field(page, **tool_input)
        elif tool_name == "get_page_text":
            return get_page_text(page)
        return f"Unknown tool: {tool_name}"

    def _build_prompt(self, history, page):
        history_text = "\n".join(
            f"Step {h['step']}: {h['action']} → {h['result']}" for h in history
        )
        return f"""Objective: {self.objective}

Current page URL: {page.url}

History so far:
{history_text if history_text else "(nothing tried yet)"}

Decide the next single action."""

    def _build_report(self, history, success, final_text):
        return {"objective": self.objective, "success": success,
                "summary": final_text, "steps_taken": len(history),
                "full_history": history}

    def run(self, page):
        history = []
        for step in range(MAX_STEPS):
            prompt = self._build_prompt(history, page)
            response = self.client.messages.create(
                model=self.model, max_tokens=1024,
                system=self.instructions,
                messages=[{"role": "user", "content": prompt}],
                tools=TOOL_DEFINITIONS
            )
            tool_used = False
            for block in response.content:
                if block.type == "tool_use":
                    tool_used = True
                    result = self.execute_tool(block.name, block.input, page)
                    history.append({"step": step,
                        "action": f"{block.name}({block.input})",
                        "result": result})
                elif block.type == "text" and "TASK COMPLETE" in block.text:
                    return self._build_report(history, True, block.text)
            if not tool_used:
                return self._build_report(history, False, response.content[0].text)
        return self._build_report(history, False,
            "Stopped: exceeded maximum step limit.")

Running It — main.py

from playwright.sync_api import sync_playwright
from agent import QAAgent
import os

agent = QAAgent(api_key=os.environ["ANTHROPIC_API_KEY"])
agent.set_objective(
    "Verify that a user with valid credentials can successfully "
    "log into ShopEasy, ending up on their account dashboard."
)

with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.goto("https://staging.shopeasy.example.com/login")

    report = agent.run(page)

    print(f"Success: {report['success']}")
    print(f"Summary: {report['summary']}")
    print(f"Steps taken: {report['steps_taken']}")
    for h in report['full_history']:
        print(f"  Step {h['step']}: {h['action']} → {h['result']}")

    browser.close()

The ONE genuinely AI-powered line:

Everything else is ordinary code:

This is a genuinely useful thing to point out explicitly — "the AI part" is a small, specific, identifiable piece of a system that's mostly ordinary, well-understood software engineering around it, not some pervasive, mysterious force running through every line.

Why does this page's complete agent still work correctly if the objective is changed to something entirely different, like testing search instead of login, without any code changes?▾

Because the code was deliberately built with the objective as a genuine, swappable input — nothing in agent.py itself hardcodes anything specific to login, exactly the appropriately-scoped-objective principle from earlier in this chapter, now visible in the actual architecture.

What's genuinely LOGIN-SPECIFIC in this complete file:
Literally nothing in agent.py itself — only the OBJECTIVE

What would happen with a DIFFERENT objective:
agent.set_objective("Verify that searching for 'wireless mouse'

This is a genuinely meaningful design outcome, not an accident — keeping the objective as the one task-specific input, with everything else genuinely general, is exactly what makes this small agent a real foundation rather than a one-off script that only works for login.

If this agent's real run took 12 out of its 15 available steps to verify a simple login — more than the 4-step example shown on this page — what would you investigate, and how?▾

I'd review the full_history in the report first — this chapter's own _build_report retains it specifically for this kind of investigation — looking for repeated or seemingly unnecessary steps rather than assuming something is fundamentally broken just because it succeeded.

What to look for in full_history:
- Are any ACTIONS genuinely repeated (the same fill_field call
  appearing more than once)? This might indicate the agent
  retried something that should have succeeded the first time
- Is the agent calling get_page_text MORE often than seems
  necessary, perhaps re-checking things it should already know
  from earlier in its own history?
- Does the SEQUENCE make logical sense for a simple login, or
  does it show genuinely confused, roundabout reasoning?

Also worth checking:
Is the REAL page itself more complex than the simple example
  assumes — an extra confirmation step, a CAPTCHA, a genuinely
  slower-loading element requiring more back-and-forth? Some
  legitimate real-world pages ARE more complex than a 4-step
  minimal example, which wouldn't indicate a bug at all.

The key habit this illustrates: a successful run that took notably more steps than expected is worth a quick look at the actual history before assuming everything's fine — sometimes it reveals a real inefficiency worth fixing, and sometimes it reveals the real page genuinely needed more steps, which is itself useful information.
