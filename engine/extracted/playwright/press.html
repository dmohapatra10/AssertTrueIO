What is press()?

locator.press(key: string, options?: { delay?: number })
page.keyboard.press(key: string)

press() sends a single key or key combination — Enter, Escape, Tab, or a combo like Control+A — dispatching a real keydown/keyup pair. It exists on both a locator (focuses the element first) and on page.keyboard directly (uses whatever currently has focus).

Why it's important

Some interactions are keyboard-only by nature — submitting a form with Enter, dismissing a modal with Escape, navigating a custom dropdown with arrow keys — and testing them properly means testing the actual keyboard interaction, not simulating the same outcome via a click that happens to trigger the same code path.

Key Naming Syntax

ExampleMeaning
EnterSingle key
EscapeSingle key
Control+AKey combination (Cmd+A is written the same way on Mac; Playwright maps Control to Meta automatically per OS convention when relevant)
Shift+TabReverse-tab combination
ArrowDownArrow keys, by full name

Basic Example

await page.getByLabel('Search').fill('playwright');
await page.getByLabel('Search').press('Enter');

Detailed Example — Keyboard-Only Modal Dismissal

test('pressing Escape closes the modal', async ({ page }) => {
  await page.goto('/dashboard');
  await page.getByRole('button', { name: 'Settings' }).click();
  await expect(page.getByRole('dialog')).toBeVisible();

  await page.keyboard.press('Escape');
  await expect(page.getByRole('dialog')).toBeHidden();
});

Using page.keyboard.press() here (rather than a locator's press()) is deliberate — Escape is a global keyboard interaction, not tied to a specific focused field.

Real-World Example — Arrow-Key Navigation in a Custom Dropdown

test('arrow keys navigate a custom combobox', async ({ page }) => {
  await page.goto('/settings');

  const combobox = page.getByRole('combobox', { name: 'Timezone' });
  await combobox.click();
  await combobox.press('ArrowDown');
  await combobox.press('ArrowDown');
  await combobox.press('Enter');

  await expect(combobox).toHaveValue(/Pacific/);
});

Custom-built dropdowns (not native <select>) often implement their own arrow-key handling, and this is exactly the case where selectOption() won't work — the interaction genuinely needs to be driven by keyboard events, since that's how the component itself is built.

❌ Fragile vs. ✅ Recommended

// ❌ Clicking a visible "Close" icon when the real requirement is keyboard accessibility
await page.getByRole('button', { name: 'Close' }).click();

// ✅ If Escape-to-close is a stated requirement, test the actual keyboard path
await page.keyboard.press('Escape');
await expect(page.getByRole('dialog')).toBeHidden();

Common Mistakes

  • Using locator.press() when the interaction isn't tied to a specific field (like Escape) — page.keyboard.press() is more accurate for global shortcuts.
  • Assuming press('Enter') always submits a form — it only does if there's a keydown/submit handler wired up to respond to it; if not, this correctly reveals the form isn't keyboard-submittable, which may be a real bug.
  • Forgetting an element needs focus before page.keyboard.press() affects it — unlike locator.press(), which focuses first automatically, page.keyboard.press() acts on whatever currently has focus.

Edge Cases

  • OS-specific modifier keys (Cmd on Mac vs. Ctrl on Windows/Linux) — for cross-platform shortcut testing, branch on process.platform or use Playwright's ControlOrMeta alias where supported, rather than hardcoding one OS's convention.
  • Holding a key down across multiple actions — use page.keyboard.down('Shift') / page.keyboard.up('Shift') instead of press() when a modifier needs to stay held across more than one subsequent action.

Debugging

If a key press doesn't seem to do anything, verify focus is actually where you expect it — page.keyboard.press() silently does nothing meaningful if focus is on the wrong (or no) element; checking document.activeElement via page.evaluate() can confirm this while debugging.

Best Practices

  • Use locator.press() for field-specific key interactions; use page.keyboard.press() for global shortcuts not tied to a specific element.
  • Test keyboard-only paths (Escape, Tab, arrow-key navigation) explicitly when accessibility or keyboard support is a real requirement — don't assume a click-based test covers it.

Practice Exercise

Write a test that tabs through three form fields using press('Tab') and asserts focus lands on the submit button last, without clicking anything directly.

Summary

press() sends real single-key or key-combination events — the right tool for keyboard shortcuts, form submission via Enter, and any interaction that's genuinely keyboard-driven rather than click-driven. Use the locator variant for field-specific keys, and page.keyboard for global ones.

Interview Questions

Why would you use page.keyboard.press('Escape') instead of clicking a close button to test a modal's dismiss behavior?▾
If the requirement is that the modal be dismissible via keyboard (a common accessibility requirement), clicking a visible close button doesn't actually test that path — it could pass even if Escape does nothing. Driving the interaction with the real keyboard event verifies the feature the test is meant to check.
What's the difference between locator.press() and page.keyboard.press()?▾
locator.press() focuses the element first automatically; page.keyboard.press() acts on whatever currently has focus, with no implicit focusing step.
Why would you test Escape-to-close with page.keyboard.press() instead of clicking a close button?▾
If the requirement is keyboard dismissibility, clicking a visible close button doesn't verify that Escape itself works — it could pass even if the keyboard path is broken.
How do you hold a modifier key across multiple subsequent actions?▾
Use page.keyboard.down('Shift') and page.keyboard.up('Shift') instead of press(), which only holds the modifier for a single key event.
Why might a Control+A shortcut behave differently across operating systems?▾
Mac uses Meta (Cmd) where Windows/Linux use Control by convention; cross-platform tests may need to branch on process.platform or use a ControlOrMeta alias.
