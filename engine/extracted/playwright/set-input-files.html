setInputFiles()

Prerequisites: Actions overview

What is setInputFiles()?

locator.setInputFiles(
  files: string | string[] | { name: string, mimeType: string, buffer: Buffer } | Array<...>
)

setInputFiles() sets the files on an <input type="file"> element directly, without ever opening the operating system's native file picker dialog — which, like a native <select>'s dropdown, isn't part of the page's DOM and can't be automated the way ordinary UI can.

Why it's important

File upload is one of the few interactions where "simulate what a user does" (click the input, wait for an OS dialog, click through a file browser) simply isn't automatable in a headless browser context. setInputFiles() sidesteps the entire problem by operating on the file input's underlying file list directly, then dispatching the same change event a real file selection would produce — so the app's upload-handling JavaScript runs exactly as it would for a real user.

Basic Example — Uploading from Disk

await page.getByLabel('Upload resume').setInputFiles('./test-data/resume.pdf');

Detailed Example — Multiple Files

await page.getByLabel('Upload photos').setInputFiles([
  './test-data/photo-1.jpg',
  './test-data/photo-2.jpg',
  './test-data/photo-3.jpg',
]);

await expect(page.getByTestId('upload-count')).toHaveText('3 files selected');

Real-World Example — Generating a File In-Memory

test('user can upload a generated CSV without touching disk', async ({ page }) => {
  await page.goto('/import');

  const csvContent = 'name,email\nJordan Lee,jordan@example.com\n';

  await page.getByLabel('Upload contacts CSV').setInputFiles({
    name: 'contacts.csv',
    mimeType: 'text/csv',
    buffer: Buffer.from(csvContent),
  });

  await page.getByRole('button', { name: 'Import' }).click();
  await expect(page.getByText('1 contact imported')).toBeVisible();
});

Passing an in-memory buffer instead of a path avoids needing real fixture files checked into the repo for content that's easy to generate — useful for tests that need many slightly different file variations.

Clearing a File Input

await page.getByLabel('Upload resume').setInputFiles([]); // empty array clears selection

❌ Fragile vs. ✅ Recommended

// ❌ Attempting to click the input and interact with an OS file dialog — not automatable
await page.getByLabel('Upload resume').click();
// (no way to reliably drive the native OS file picker from here)

// ✅ Set the file directly — dispatches the same change event a real selection would
await page.getByLabel('Upload resume').setInputFiles('./test-data/resume.pdf');

Common Mistakes

  • Using relative paths that depend on the current working directory — resolve fixture paths relative to the test file (e.g., via path.join(__dirname, ...)) rather than assuming a specific CWD, which differs between local runs and CI.
  • Not testing file-type/size validation — a common gap is only testing the happy path; use a generated in-memory buffer to easily produce an oversized or wrong-mimetype file and verify the app rejects it correctly.
  • Forgetting drag-and-drop file upload zones aren't <input> elements — a "drag files here" dropzone often still has a hidden <input type="file"> underneath that setInputFiles() can target directly, without needing to simulate an actual drag gesture.

Edge Cases

  • Hidden file inputs (common — many upload UIs style a button that triggers a visually-hidden <input type="file">) — setInputFiles() works on it directly regardless of its CSS visibility, since it doesn't rely on clicking to open a dialog.
  • Uploads that trigger immediately on file selection (no separate "Upload" button) — assert on the resulting upload progress/completion UI right after setInputFiles(), since the change event firing is what kicks off the upload.

Debugging

If an upload doesn't appear to trigger any app behavior, confirm the target element really is the <input type="file"> and not a wrapping button or label — setInputFiles() must be called on the actual file input itself, even if that input is visually hidden behind other UI.

Best Practices

  • Keep small fixture files in a dedicated test-data folder, referenced via absolute paths built from __dirname.
  • Use in-memory buffers for generated or parameterized file content instead of maintaining many near-duplicate fixture files.
  • Test both the happy path and validation failures (wrong type, oversized file) — file upload is a common area for under-tested edge cases.

Practice Exercise

Write a test that generates a plain-text file in memory larger than an app's stated 5MB limit and asserts the correct validation error appears, without keeping a large fixture file in the repository.

Summary

setInputFiles() sets a file input's value directly, bypassing the unautomatable native OS file picker, and works equally well with real files on disk or generated in-memory buffers. It's the only reliable way to test file upload in a headless browser context.

Interview Questions

Why can't Playwright automate a native OS "Choose File" dialog the way it clicks buttons or fills text fields?▾
The OS file picker is a native operating-system dialog rendered entirely outside the browser's page content and DOM — Playwright's automation model operates on the page, not the OS. setInputFiles() avoids the problem altogether by setting the file input element's file list directly and dispatching the same change event a real selection would produce, so the app's upload logic behaves identically without ever needing to interact with a real dialog.
Why can't Playwright automate the native 'Choose File' OS dialog?▾
It's rendered entirely outside the browser page by the operating system, outside what browser automation protocols can control.
How do you upload a file without keeping it as a fixture on disk?▾
Pass an object with name, mimeType, and a Buffer to setInputFiles() instead of a file path.
How do you clear a file input's current selection?▾
Call setInputFiles([]) with an empty array.
Does setInputFiles() require the target input to be visible?▾
No — it works even on a visually hidden <input type="file">, which is common behind styled upload buttons.
