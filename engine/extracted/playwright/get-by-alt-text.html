Beginner

getByAltText()

Prerequisites: Locators overview

What is getByAltText()?

page.getByAltText(text: string | RegExp, options?: { exact?: boolean })

getByAltText() finds an image (or any element supporting an alt attribute, like <area> or <input type="image">) by its alt text — the description shown when an image fails to load, and read aloud by screen readers.

Why it's important

Images are common interactive targets in e-commerce and media-heavy apps (product thumbnails, avatar pickers, icon buttons implemented as <img>), and alt text is the only accessible way to identify them. As with the other semantic locators, a missing or unmatched getByAltText() call is often flagging a real accessibility gap — an image with no meaningful alt attribute.

Basic Example

await page.getByAltText('Wireless Mouse product photo').click();

Detailed Example — Product Gallery

test('clicking a thumbnail updates the main product image', async ({ page }) => {
  await page.goto('/products/wireless-mouse');

  await page.getByAltText('Wireless Mouse — side view').click();
  await expect(page.getByAltText('Wireless Mouse — main image')).toHaveAttribute(
    'src', /side-view/
  );
});

Real-World Example — Avatar Selection

test('user can pick a new profile avatar', async ({ page }) => {
  await page.goto('/settings/profile');
  await page.getByAltText('Astronaut avatar option').click();
  await page.getByRole('button', { name: 'Save changes' }).click();

  await expect(page.getByAltText('Current profile avatar')).toHaveAttribute(
    'src', /astronaut/
  );
});

❌ Fragile vs. ✅ Recommended

// ❌ Coupled to a generated filename that changes on every image re-upload
await page.locator('img[src*="img_48291.jpg"]').click();

// ✅ Coupled to meaning, not the file
await page.getByAltText('Wireless Mouse product photo').click();

Common Mistakes

  • Assuming every <img> has usable alt text — decorative images often intentionally have alt="", which is correct practice but means getByAltText() can't target them; that's expected, not a bug.
  • Using generic alt text like "image" or "photo" across multiple images, causing strict-mode collisions — this is usually worth raising as a content issue in the app, not just worked around in the test.

Edge Cases

  • Background images set via CSS have no alt attribute at all — they're not real DOM images and getByAltText() cannot target them; look for a wrapping element with a role or test ID instead.
  • SVG icons used as images — an inline <svg> doesn't have alt; use <title> inside the SVG with getByTitle(), or role="img" with getByRole(), instead.

Debugging

If a locator can't find an obviously visible image, check the DOM for the alt attribute directly — a common cause is the alt text being set dynamically by JavaScript after an initial render, in which case Playwright's auto-waiting still applies but the exact text used in the locator must match the final rendered value.

Best Practices

  • Use specific, descriptive alt text for any image the test needs to target — this benefits both accessibility and test stability at once.
  • Don't try to force getByAltText() onto decorative images that correctly have empty alt text — target a nearby element with a role or test ID instead.

Practice Exercise

A product page shows four color-swatch thumbnails, all with alt text "Color swatch." Rewrite the locator strategy (in the app or the test) so each swatch can be targeted individually.

Summary

getByAltText() locates images and image-like elements via their alt attribute, doubling as a check that images are genuinely accessible. A missing match is often better fixed in the app's markup than worked around in the test.

Interview Questions

Why can't getByAltText() find a decorative background image applied via CSS?▾
A CSS background image is not a DOM <img> element and has no alt attribute at all — it's a styling detail, not accessible content — so there's nothing for getByAltText() to read; a different locator targeting the containing element is needed instead.
Why might getByAltText() fail to find an obviously visible image?▾
The image may correctly have alt="" as a decorative image, or it might be a CSS background image, which has no alt attribute at all.
What does a getByAltText() failure often actually indicate?▾
A real accessibility gap — the image lacks meaningful alt text, which affects screen reader users too.
Can getByAltText() target an SVG icon?▾
Only if the SVG has an alt-equivalent like a nested <title> or role="img"; a plain inline SVG icon has no alt attribute to match against.
Why is generic alt text like 'photo' a problem for testing?▾
It causes strict-mode collisions when multiple images share the same generic text, and it's also a weak accessibility label for real users.
