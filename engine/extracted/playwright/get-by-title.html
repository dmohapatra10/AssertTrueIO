Beginner

getByTitle()

Prerequisites: Locators overview

What is getByTitle()?

page.getByTitle(text: string | RegExp, options?: { exact?: boolean })

getByTitle() finds an element by its title attribute — the text shown in the small native tooltip that appears after hovering for a moment.

Why it's a niche locator

The title attribute is used sparingly in modern web apps — most custom tooltips today are built with JavaScript/CSS (a styled <div>, not the native title attribute), which getByTitle() cannot see at all. This locator is mainly useful for icon buttons or status indicators that specifically rely on the native title tooltip, or third-party widgets/charting libraries that still set it.

Basic Example

await page.getByTitle('Close dialog').click();

Detailed Example

// An icon-only close button relying on the native tooltip for its accessible name
<button title="Close dialog"><svg .../></button>

await page.getByTitle('Close dialog').click();
await expect(page.getByRole('dialog')).toBeHidden();

Real-World Example — Chart Data Points

test('hovering a chart bar reveals its tooltip title', async ({ page }) => {
  await page.goto('/analytics');
  const bar = page.getByTitle(/Revenue: \$[\d,]+/);
  await expect(bar).toBeVisible();
});

Some charting libraries render each data point as an SVG element with a native title — this is one of the more realistic places getByTitle() shows up in production test suites.

❌ Fragile vs. ✅ Recommended

// ❌ Assuming a custom-styled tooltip is a native title attribute
await page.getByTitle('Delete item').click(); // fails — this tooltip is a styled <div>, not title=""

// ✅ Verify first, then use the matching locator for how it's actually built
await page.getByRole('button', { name: 'Delete item' }).click(); // native aria-label instead

Common Mistakes

  • Assuming a visible tooltip means a title attribute exists — most modern custom tooltips are separate DOM elements, not the native browser tooltip; inspect the DOM before reaching for this locator.
  • Using title as the sole accessible name for a critical interactive element — title tooltips are not reliably announced by all screen readers and aren't keyboard-accessible on their own; aria-label with getByRole() is the more robust pattern in the app itself.

Edge Cases

  • SVG <title> elements (not attributes) — some icon libraries use a nested <title> tag inside an <svg> rather than a title="" attribute; Playwright's getByTitle() handles both, but confirm which one you're looking at when debugging.

Debugging

Before writing a getByTitle() locator, hover the element in DevTools and check the Elements panel for a literal title attribute — if the tooltip is instead a sibling <div class="tooltip"> that appears on hover via CSS/JS, this locator will never match it.

Best Practices

  • Confirm the element genuinely has a title attribute before reaching for this locator — don't assume from visual tooltip behavior alone.
  • Prefer getByRole() with aria-label for interactive elements where possible; reserve getByTitle() for elements that specifically rely on the native attribute.

Practice Exercise

Given an icon button with both aria-label="Download report" and title="Download report", write both a getByRole() and a getByTitle() locator for it, and explain which one you'd choose for a real test suite and why.

Summary

getByTitle() matches the native title attribute — genuinely useful, but only for the shrinking set of elements that still use it instead of a custom-built tooltip. Always verify the attribute exists before relying on this locator.
