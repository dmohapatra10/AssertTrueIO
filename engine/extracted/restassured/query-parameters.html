Query Parameters

Prerequisites: Headers

What is this?

given()
    .queryParam("page", 2)
    .queryParam("limit", 10)
.when()
    .get("/users");
// Resulting URL: /users?page=2&limit=10

.queryParam() adds a key-value pair to the request's query string — the part of a URL after ? used for filtering, sorting, and pagination against a resource collection that already exists independent of the parameter.

Why use .queryParam() instead of building the URL string yourself?

Query values often contain characters that need URL encoding — spaces, ampersands, non-ASCII text. .queryParam() handles this automatically; hand-building a query string requires you to remember and correctly apply URLEncoder.encode() yourself, and forgetting it produces a URL that's silently malformed rather than an obvious error.

Basic Example

given()
    .queryParam("status", "active")
.when()
    .get("/users");

Multiple Values for the Same Key

given()
    .queryParam("status", "active", "pending")
.when()
    .get("/users");
// Resulting URL: /users?status=active&status=pending

Useful for APIs that accept repeated query keys to mean "match any of these values" — passing multiple arguments to a single .queryParam() call produces the key repeated once per value, exactly matching that convention.

Passing a Map of Query Parameters

Map<String, Object> params = new HashMap<>();
params.put("page", 2);
params.put("limit", 10);
params.put("sort", "created_at");

given()
    .queryParams(params)
.when()
    .get("/users");

For a request with many query parameters, especially ones built up conditionally, a Map passed to .queryParams() (plural) is often cleaner than a long chain of individual .queryParam() calls.

Real-World Example — Conditional Query Parameters

RequestSpecification request = given();

if (statusFilter != null) {
    request.queryParam("status", statusFilter);
}
if (minPrice != null) {
    request.queryParam("min_price", minPrice);
}

request.when().get("/products").then().statusCode(200);

Building a request specification up conditionally, only adding parameters that actually have a value, avoids sending an empty or null query parameter that might produce different (and unintended) behavior than omitting it entirely.

Two Different Conventions for "Multiple Values"

// Convention A: repeated key (shown earlier on this page)
given().queryParam("status", "active", "pending").when().get("/users");
// → /users?status=active&status=pending

// Convention B: a single comma-separated value — a genuinely different convention
given().queryParam("status", "active,pending").when().get("/users");
// → /users?status=active,pending

These are two real, different conventions that different APIs choose between — RestAssured's multi-argument .queryParam() call produces the repeated-key style automatically, but if an API instead expects a single comma-joined value, you need to build that string yourself and pass it as one value. Check the API's actual documentation rather than assuming; using the wrong convention typically doesn't error, it just silently filters incorrectly (an API expecting comma-separated values sees the second status=pending as an entirely separate, unrecognized parameter under convention A).

Extracting Query Parameter Values (for Verification)

Response response = given().queryParam("page", 3).when().get("/users");
String requestUri = response.getDetailedCookies().toString(); // not this —

// To confirm what was actually SENT, log it instead:
given().log().all().queryParam("page", 3).when().get("/users");

Unlike headers, RestAssured doesn't offer a direct "get the query param I sent" accessor on the response, since query parameters are a property of the request, not the response. If you need to confirm exactly what was sent, .log().all() (covered in the Building HTTP Requests overview) remains the reliable way to see the fully resolved outgoing URL.

❌ Fragile vs. ✅ Recommended

// ❌ Hand-built query string — breaks on special characters, no encoding safety
given().when().get("/products/search?q=" + searchTerm + "&category=electronics");

// ✅ Let RestAssured handle encoding
given()
    .queryParam("q", searchTerm)
    .queryParam("category", "electronics")
.when()
    .get("/products/search");

Common Mistakes

  • Hand-concatenating query strings instead of using .queryParam() — loses automatic encoding and readability both.
  • Passing a null value directly to .queryParam() without checking first — can produce an unintended empty-value parameter in the URL rather than correctly omitting it.
  • Using a query parameter where a path parameter belongs — a value that identifies which specific resource you mean belongs in the path, not the query string.

Edge Cases

  • Boolean and numeric values — .queryParam("active", true) and .queryParam("limit", 10) both work directly; RestAssured converts them to their string representation automatically.
  • Empty string vs. omitted parameter — these can mean genuinely different things to an API; be deliberate about which one you're actually sending.

Debugging

If you're unsure what query string a chain of .queryParam() calls actually produces, add .log().all() to print the fully resolved outgoing URL before the request is sent.

Best Practices

  • Always use .queryParam()/.queryParams() rather than hand-building query strings.
  • Only add a query parameter when it has a real, intentional value — don't pass null or empty values without deliberate reason.
  • Use a Map via .queryParams() once a request has more than three or four query parameters.

Practice Exercise

Write a test against a search endpoint that conditionally adds a category filter, a minimum price, and a maximum price — only including each parameter when its corresponding value is non-null — and confirm via .log().all() that the resulting URL reflects exactly the parameters you intended.

Summary

.queryParam() and .queryParams() build a request's query string safely, handling URL encoding automatically — the tool of choice over hand-built strings for anything filtering, sorting, or paginating within an existing resource collection.
