Seeing What Your Tests Are Actually Doing

Earlier pages have mentioned logging in passing — a .log().all() here, a debugging tip there. Logging deserves its own treatment, because it's the difference between a failed test that tells you exactly what went wrong and one that leaves you guessing. Four pages:

  1. Request Logging — seeing exactly what you're about to send
  2. Response Logging — seeing exactly what came back
  3. Conditional Logging — the CI-friendly pattern real projects use
  4. Custom Logging & Filters — integrating with real logging frameworks instead of raw console output

Why This Comes Right Before Specifications

Good logging habits genuinely need to be in place before you start building shared, reused request specifications next — once request construction gets abstracted behind a shared RequestSpecification, debugging "what did this actually send" becomes harder unless logging is already a comfortable, well-understood tool. Establishing it now, while requests are still simple and explicit, pays off directly once things get more abstracted.

The Core Tension to Resolve

Logging every request and response in full detail is enormously useful while actively debugging — and enormously unhelpful in a CI pipeline running hundreds of passing tests, where it produces a wall of noise that makes finding the one genuine failure harder, not easier. Each page ahead builds toward resolving that tension: log everything while you're actively working on a test, log almost nothing once it's committed and passing reliably, and log automatically and completely the instant something actually fails.

A Quick Preview

// While actively debugging — verbose, temporary
given().log().all().when().get("/users/2");

// In committed test code — silent unless something goes wrong
.then().log().ifValidationFails().statusCode(200);

// Project-wide — every request/response logged automatically via a filter
RestAssured.filters(new RequestLoggingFilter(), new ResponseLoggingFilter());

These three lines represent the three levels this chapter covers, from most temporary/manual to most permanent/automatic. Start with Request Logging below.
