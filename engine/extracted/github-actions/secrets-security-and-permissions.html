The Chapter That Matters Most If You Get It Wrong

Everything else in this course, done badly, produces a broken pipeline. This chapter, done badly, can produce a genuine security incident — a leaked password, a compromised deployment, a supply-chain attack through a malicious third-party action. Five focused pages, deliberately practical:

  1. Why Secrets Matter & Using GitHub Secrets — the problem, and the three scopes GitHub gives you
  2. Variables vs. Secrets: Choosing the Right One — a real, easy-to-get-wrong distinction
  3. GITHUB_TOKEN: The Automatic Token Explained — the token every workflow already has, whether you use it or not
  4. Workflow Permissions & Least Privilege — giving a workflow exactly the access it needs, no more
  5. Common Security Mistakes & a Security Challenge — real vulnerable workflows, for you to actually fix

Why This Chapter Is Different From the Others

A YAML mistake fails loudly — you see it immediately in the Actions tab. A security mistake often doesn't fail at all; it just quietly works, exposing something it shouldn't have, until someone notices for the wrong reason. That asymmetry is exactly why this chapter treats security as a genuine, first-class topic rather than an afterthought.

Common Mistakes to Watch For

  • Hardcoding a password or API key directly in a workflow file — visible to anyone with repository access, permanently, in the file's own history.
  • Printing a secret's value to the workflow log "just to debug" — logs can be more widely visible than the secret itself ever should be.
  • Granting a workflow far more permission than it actually needs, because it's easier than figuring out the minimum required.

What You'll Be Able to Do

By the end of the five pages that follow, you should be able to store and use secrets correctly across all three scopes, know precisely when a value belongs in secrets versus vars, understand what GITHUB_TOKEN actually is and does, apply least-privilege permissions deliberately, and — this chapter's own security challenge — take a genuinely insecure workflow and fix it yourself.
