What Happens to a Job's Output Once It's Done?

Chapter 4 established that each job gets a completely fresh runner, destroyed once the job finishes — meaning anything a job produces (a built file, a test report, a screenshot) disappears along with it, unless deliberately preserved. Artifacts are that deliberate preservation mechanism. Four focused pages:

  1. What is an Artifact? & Uploading Artifacts — the concept, and actually publishing one
  2. Downloading Artifacts & Passing Data Between Jobs — using an artifact from a different job
  3. Test Reports, Screenshots & Videos in CI — the specific, genuinely common use case for automation testing
  4. Artifact vs. Cache: Choosing the Right One — a real decision most people get wrong at least once

The Real-World Scenario This Chapter Builds

Test job generates reports → upload → another job publishes them

This single sentence needs exactly the first two pages of this chapter working together — one job uploading something, a genuinely different job downloading and using it.

Common Mistakes to Watch For

  • Assuming a file created in one job is automatically visible to another — it isn't, and artifacts exist specifically to bridge that gap deliberately.
  • Confusing an artifact with a cache — genuinely different tools solving genuinely different problems, covered explicitly on this chapter's final page.
  • Only uploading test reports on success — a failure is often exactly when a report is most valuable, and this chapter covers exactly how to make sure it still gets published.

What You'll Be Able to Do

By the end of the four pages that follow, you should be able to upload and download artifacts between jobs, correctly publish test reports and screenshots (including specifically when a test fails), and confidently choose between an artifact and a cache for any given real need.
