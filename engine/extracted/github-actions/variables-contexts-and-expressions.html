Variables, Contexts & Expressions

Prerequisites: Working with Code in CI

From Static Workflows to Dynamic Ones

Every workflow so far has done the exact same thing on every single run. Real pipelines need to behave differently depending on context — which branch, whether earlier steps succeeded, what a previous step actually produced. This chapter is where workflows stop being static scripts and start making genuine decisions. Four focused pages:

  1. Environment Variables: env: and Job vs. Step Scope — defining values once, using them everywhere
  2. GitHub Actions Contexts Explained — the built-in information every workflow has access to
  3. Expressions: The ${{ }} Syntax — the mechanism that actually reads all of this dynamic information
  4. Conditional Execution: if: — making a step or job actually decide whether to run

A Quick Preview of Where This Is Heading

if: github.ref == 'refs/heads/main' && needs.test.result == 'success'

This single line combines almost everything in this chapter — a context (github.ref), a comparison, another context tied to a previous job's outcome (needs.test.result), and a conditional. By the end of this chapter, a line like this should read as something you understand completely, not something you'd only copy from an example.

The Real-World Requirement This Chapter Builds Toward

Requirement: "Run deployment only when tests pass and the workflow
              runs on the main branch."

This is a genuinely common, real requirement, and it needs exactly the tools this chapter covers — a context to check which branch triggered the run, a way to check whether a previous job actually succeeded, and a conditional to act on both.

Common Mistakes to Watch For

  • Confusing an environment variable with a context — they're genuinely different mechanisms, covered distinctly in this chapter.
  • Forgetting the ${{ }} wrapper when trying to use a context or expression value — without it, YAML often just treats the text as a literal string.
  • Writing an if: condition that looks right but evaluates unexpectedly — expression evaluation has real, learnable rules, not something to guess at.

What You'll Be Able to Do

By the end of the four pages that follow, you should be able to define and correctly scope environment variables, read from any of GitHub Actions' built-in contexts, write expressions confidently, and build real conditional logic — including the exact "deploy only if tests passed and we're on main" pattern that opened this chapter.
