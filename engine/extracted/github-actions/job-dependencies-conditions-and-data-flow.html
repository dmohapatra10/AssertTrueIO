Formalizing Something You've Already Used

needs: has appeared in examples since Chapter 6 — conditioning deployment on a test job's outcome, downloading an artifact only after its job finishes — without ever being taught as its own topic. This chapter finally gives it, and its two genuinely new companions (passing real values between steps and between jobs), full treatment. Four focused pages:

  1. Job Dependencies: needs: In Depth — single and multiple dependencies, fully explained
  2. Passing Information Between Steps — the actual mechanism behind steps.<id>.outputs
  3. Passing Information Between Jobs — small values, not files — genuinely different from artifacts
  4. Conditional Jobs & Failure Handling — the complete status vocabulary, and designing a pipeline around it

The Real Pipeline This Chapter Builds

Build
  ↓
Unit Tests
  ↓
API Tests
  ↓
UI Tests
  ↓
Deploy

This looks like a strict, linear chain — but it doesn't have to be. API Tests and UI Tests might genuinely be independent of each other, both only needing Build to finish first, meaning they could run in parallel rather than one waiting for the other. Deciding which jobs truly need to wait for which is exactly what this chapter is about.

Common Mistakes to Watch For

  • Chaining every job sequentially "to be safe," even when two jobs are genuinely independent and could run in parallel, needlessly slowing the whole pipeline down.
  • Confusing a step output with a job output — related mechanisms, but genuinely different scopes, covered as two distinct pages here.
  • Treating "skipped" the same as "failed" when designing conditional logic — they're genuinely different states with different correct handling.

What You'll Be Able to Do

By the end of the four pages that follow, you should be able to design a multi-job pipeline that correctly parallelizes independent work, pass a value from one step to a later one, pass a value from one job to an entirely different job, and build conditional logic that correctly distinguishes success, failure, cancellation, and skipping.
