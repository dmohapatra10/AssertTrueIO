Why This Comes Right After Chapter 1, Not Later

Chapter 1 already showed one real YAML bug — a runs-on line indented incorrectly, breaking the entire workflow. That wasn't a one-off example; YAML formatting mistakes are genuinely one of the most common sources of workflow failures, especially early on. Understanding the language itself properly, before writing more complex workflows in later chapters, prevents a huge fraction of confusing, hard-to-diagnose problems later.

A Quick Preview

name: My Workflow        # a key-value pair
on: push                 # another key-value pair
jobs:                    # a key whose value is a nested structure
  build:                 # nested one level under jobs
    runs-on: ubuntu-latest
    steps:                # a list, indicated by the dash below
      - run: echo "hi"
      - run: echo "bye"

Every workflow you'll ever write is built from exactly these few ideas — key-value pairs, nesting via indentation, and lists via a leading dash. Nothing more exotic than that underlies even the most complex real-world pipeline.

Common Mistakes to Watch For

  • Mixing tabs and spaces for indentation — YAML requires consistent spaces; a stray tab character can break parsing in ways that are genuinely hard to see by eye.
  • Treating YAML like it doesn't care about indentation depth — unlike some languages, indentation in YAML isn't cosmetic, it's structural; a different indent level means a different, real, meaning.
  • Not distinguishing a list from a nested key-value structure — the dash (-) specifically signals a list item; without it, you're describing something different entirely.
