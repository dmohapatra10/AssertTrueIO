From Toy Examples to a Real Pipeline

Every workflow so far has been deliberately minimal — a single echo, or a bare npm test with no real setup around it. This chapter builds the actual, complete sequence a genuinely useful CI pipeline needs. Five focused pages:

  1. Checking Out Repository Code — actions/checkout, properly understood
  2. Setting Up Programming Languages: Java, Node.js & Python — getting a real language runtime onto the runner
  3. Installing Dependencies & Caching — installing what your project needs, and not redoing it every single run
  4. Building the Application & Running Unit Tests — turning source code into something real, then verifying it
  5. Running Automation Tests: Playwright, RestAssured & k6 — connecting this course to the site's other three tracks

The Real Pipeline This Chapter Builds

Checkout
   ↓
Setup Java/Node
   ↓
Install Dependencies
   ↓
Build
   ↓
Run Tests
   ↓
Publish Results

This is genuinely the shape of a huge fraction of real-world CI pipelines across every language and framework — the specifics change, but this sequence itself barely does.

Common Mistakes to Watch For

  • Forgetting actions/checkout entirely — a fresh runner has no code on it at all; every later step depends on this happening first.
  • Reinstalling dependencies from scratch on every single run — without caching, a pipeline can spend a genuinely significant fraction of its total time on this one repeated step.
  • Treating "the build passed" as equivalent to "the tests passed" — these are two different, sequential questions, and a pipeline needs to actually ask both.
