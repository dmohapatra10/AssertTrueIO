What is this?

An agent's K6 tools are genuinely different in shape from Chapters 5 and 6's tools — one "action" here means running an entire load test script, which takes real time and produces a rich, aggregate summary, not a single instant result.

A Genuinely Different Kind of Tool

# tools.py
import subprocess, json

def run_k6_test(script_path, summary_export_path="summary.json"):
    result = subprocess.run(
        ["k6", "run", "--summary-export", summary_export_path, script_path],
        capture_output=True, text=True, timeout=300
    )
    with open(summary_export_path) as f:
        summary = json.load(f)
    return {
        "exit_code": result.returncode,
        "metrics": summary.get("metrics", {}),
    }

🧠 Think About It

Why might it be a genuine mistake to reuse Chapter 6's 10-second timeout for this chapter's run_k6_test tool, even though "shorter timeouts are generally safer" might seem like a reasonable default? A timeout that's too short for what a tool is genuinely, legitimately supposed to do doesn't add safety — it just breaks the tool's normal, correct operation. A load test that's deliberately running for several minutes to simulate sustained, realistic traffic isn't "stuck" at the 10-second mark; a timeout needs to reflect the tool's actual, intended behavior, not an arbitrarily short "safe-sounding" number applied without genuine consideration of what the tool actually does.

⚠️ Common Mistake

Setting every tool's timeout to the same generic value, without considering what each specific tool is actually supposed to do. Chapter 6's request timeout and this page's load-test timeout are both genuine, sensible guardrails — they're just sensible at very different actual durations, precisely because the underlying operations are genuinely different in kind.

Best Practices

  • Set each tool's timeout based on that specific tool's actual, genuine expected duration, not a generic, one-size-fits-all value.
  • Use a testing tool's structured export format (like K6's --summary-export) rather than parsing human-readable console output.
  • Recognize that "one action" can mean genuinely different things across different testing surfaces — a single request, or an entire multi-minute load test.

🎯 Key Takeaway
