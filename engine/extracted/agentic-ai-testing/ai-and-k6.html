A Third Surface, a Genuinely Different Kind of Correctness

Chapter 5 taught an agent to reason about what's on screen. Chapter 6 taught it to reason about response data. Performance testing asks a genuinely different question: not "is this response correct," but "does the system stay fast and stable under real, realistic load." Seven focused pages:

  1. Connecting an AI Agent with K6 — tools for running and reading load test results
  2. AI-Driven Load Test Design — deciding what load pattern actually fits the goal
  3. AI Threshold and Scenario Construction — setting genuinely meaningful pass/fail criteria
  4. AI Performance Results Analysis — exact and fuzzy checks, applied to performance metrics
  5. Autonomous Performance Testing — every piece working together on a real load test
  6. AI-Generated K6 Scripts — from a validated scenario to real, running K6 JavaScript
  7. Anomaly and Trend Detection — what a single run can't tell you, that several runs over time can

Common Mistakes to Watch For

  • Letting an agent pick an arbitrary load level without connecting it to a genuine, real-world usage estimate — this chapter's design page addresses this directly.
  • Setting thresholds that are either meaninglessly loose or unrealistically strict — genuinely useful thresholds need real reasoning, not an arbitrary guess.
  • Treating one successful load test run as proof of stable, ongoing performance — exactly why this chapter's final page exists.

What You'll Be Able to Do

By the end of the seven pages that follow, you should be able to give an agent genuine load-testing tools, have it design a load scenario that actually fits a real goal, set thresholds with real reasoning behind them, analyze results with the right kind of check for each situation, watch it run a performance test autonomously, generate real K6 scripts from a validated scenario, and reason about trends across multiple runs, not just one.
