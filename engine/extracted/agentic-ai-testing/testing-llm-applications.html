Testing LLM Applications

Prerequisites: Autonomous API Testing

Turning the Lens Around

Every chapter so far used AI to test applications that don't themselves use AI — ShopEasy's checkout, orders API, and search are all genuinely deterministic underneath. This chapter is about something different: testing a feature where the thing being tested is itself an LLM. Seven focused pages:

  1. Why LLM Applications Are Different — no single correct output to compare against
  2. Prompt Testing — treating a prompt itself as something with real, testable behavior
  3. Response Validation for LLM Outputs — genuinely distinct from validating a JSON API response
  4. Evaluation Dimensions — relevance, correctness, groundedness, and consistency together
  5. Hallucination Testing — catching confident, fabricated claims specifically
  6. LLM Evaluation and LLM-as-a-Judge — using a second model to evaluate the first, carefully
  7. AI Test Metrics — quantifying quality across many evaluations, not just pass or fail

The Running Example for This Chapter

ShopEasy's AI Shopping Assistant — a chatbot answering real
customer questions:

"What's your return policy for electronics?"
"Is the Ergo Wireless Mouse compatible with Mac?"
"Where's my order #1042?"

Genuinely rich material for this whole chapter: a wrong
answer here isn't a stack trace or a failed assertion — it's
a customer being told something confidently, fluently, and
possibly completely wrong.

Common Mistakes to Watch For

  • Testing an LLM feature the same way as a deterministic one — this chapter's opening page is explicit about why exact-match assertions genuinely don't work here.
  • Treating "sounds confident" as evidence of "is correct" — exactly Chapter 2's original warning about LLMs, now the central risk in the feature being tested, not just the agent doing the testing.
  • Using an LLM to evaluate another LLM without any real safeguards — this chapter's LLM-as-a-Judge page is honest about the real risks this specific technique carries.

What You'll Be Able to Do

By the end of the seven pages that follow, you should be able to explain why LLM features need a genuinely different testing approach, test prompts as real artifacts with real behavior, validate free-text responses meaningfully, evaluate answers across several real dimensions, specifically catch hallucinated claims, use LLM-as-a-Judge responsibly, and turn all of this into metrics that track quality over time rather than a single pass/fail.
