The Course Turns on Itself

Chapter 11 tested applications that use an LLM. This chapter goes one step further — testing the AGENT itself, the exact kind of system Chapters 2 and 3 taught you to build. Every architecture piece from Chapter 2 (planning, tools, memory, state, loops) becomes something you now verify, not just something you construct. Seven focused pages:

  1. Why AI Agents Need Testing — a working agent isn't the same as a correctly-behaving one
  2. Testing Agent Planning — is the rough plan actually reasonable, given the goal?
  3. Testing Tool Selection and Parameters — the right tool, called correctly
  4. Testing Agent Memory — does it genuinely retain what it should?
  5. Testing Agent State — does its tracked state match reality?
  6. Testing Agent Recovery — what happens when something goes wrong mid-task?
  7. Agent Evaluation and Performance Metrics — quantifying agent quality across many runs

Common Mistakes to Watch For

  • Confirming an agent reaches the right final outcome without checking HOW it got there — a correct result from unsound reasoning is a genuine, real risk, not a pass.
  • Treating agent testing as identical to testing the LLM applications from Chapter 11 — an agent has genuinely more moving parts (tools, memory, state, loops) that each need their own verification.
  • Only testing an agent's happy path — this chapter's Recovery page exists specifically because real agents encounter real, unexpected obstacles.

What You'll Be Able to Do

By the end of the seven pages that follow, you should be able to verify an agent's plan is genuinely reasonable, confirm it selects and parameterizes tools correctly, check that memory and state stay accurate throughout a run, test how it recovers from real obstacles, and turn all of this into genuine, trackable metrics.
