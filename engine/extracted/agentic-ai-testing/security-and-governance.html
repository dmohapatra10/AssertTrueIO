Beyond MCP's Own Scope

Chapter 13's MCP Security page covered a specific, real risk — tool poisoning and scope discipline for shared, reusable servers. This chapter is broader: security and governance for the entire AI QA practice, including risks that exist whether or not MCP is involved at all. Seven focused pages:

  1. AI Security Risks in Testing — the genuine threat model for AI-powered testing specifically
  2. Prompt Injection Risks — malicious content in what an agent observes, not just what it's told
  3. Data Privacy in AI Testing — PII flowing through prompts and Chapter 15's own extensive logs
  4. Access Control for AI Agents — who can trigger, configure, and extend an agent's capabilities
  5. Audit Trails for AI Actions — accountability records, genuinely distinct from Chapter 15's debugging traces
  6. Responsible AI Testing — bias, fairness, and appropriate use in testing contexts
  7. Compliance and Governance Frameworks — external requirements and internal policy, together

A Deliberate Note on This Chapter's Relationship to Chapter 13

Chapter 13's security page was scoped specifically to MCP servers used by multiple, possibly untrusted clients. This chapter's risks exist independent of MCP entirely — a single, hardcoded agent (Chapter 3's own QAAgent) can still encounter prompt injection through page content, still handle real customer PII in test data, still needs access control over who can trigger it. This chapter is the broader practice; Chapter 13 was one specific, important slice of it.

Common Mistakes to Watch For

  • Assuming security only matters once MCP or multi-client sharing is involved — this chapter's risks apply to any AI-powered testing system.
  • Treating Chapter 15's debugging traces as sufficient for compliance accountability — this chapter's Audit Trails page is explicit about why they're genuinely different records.
  • Bolting on governance after a system is already in production — this chapter's closing page argues for building it in from the start.

What You'll Be Able to Do

By the end of the seven pages that follow, you should be able to reason about AI-specific security risks, recognize and defend against prompt injection, handle test data responsibly, control access appropriately, maintain genuine audit trails, test responsibly, and understand what a real governance framework needs to cover.
