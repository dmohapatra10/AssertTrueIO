A New Scale of Decision

Chapter 8 diagnosed one failure in depth. Chapter 9 detected flakiness in one test's history. This chapter is about decisions at PIPELINE scale — given a code change, which of hundreds of tests are actually relevant; given twenty failures in one run, which need a human right now; given one failure, is a retry genuinely warranted or just a mask. Seven focused pages:

  1. Why AI in CI/CD? — what genuinely changes at pipeline scale
  2. AI-Powered Pipeline Design — reasoning about stage structure and dependencies
  3. Intelligent Test Selection and Prioritization — running what matters, in the order that surfaces problems fastest
  4. Failure Triage in CI/CD — routing many failures, not diagnosing one
  5. AI-Powered Retry Logic — a classification-driven decision, not Chapter 9's warned-against mask
  6. Pipeline Optimization — using historical run data to genuinely speed things up
  7. CI/CD Metrics and Insights — the dashboard that ties this chapter together

A Deliberate Note on This Chapter's Relationship to Chapters 8 and 9

Two of this chapter's pages might look like repeats at first glance. They aren't: Failure Triage is about routing MANY failures across a pipeline run, not diagnosing ONE the way Chapter 8 did. AI-Powered Retry Logic is explicitly built on top of Chapter 9's warning that blind retries mask flakiness — this chapter's retry logic only retries what a genuine classification suggests is actually transient.

Common Mistakes to Watch For

  • Treating "intelligent" test selection as skipping tests without evidence — this chapter's approach is about genuine relevance, not arbitrary trimming.
  • Retrying every failure by default — exactly the mask Chapter 9 warned against, now revisited with a genuine, classification-based alternative.
  • Optimizing a pipeline for speed alone, at the cost of genuine signal — this chapter's later pages are explicit that speed and reliability need to be balanced, not traded off blindly.
