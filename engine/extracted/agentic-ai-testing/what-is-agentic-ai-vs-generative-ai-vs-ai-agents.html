What is Agentic AI? AI vs. Generative AI vs. AI Agents

Prerequisites: Introduction to Agentic AI Testing overview

What is this?

Three terms get used almost interchangeably in casual conversation, but they mean genuinely different things — and the difference matters once you're actually deciding what tool to reach for on a real QA problem.

AI — The Broad Umbrella

"AI" covers any system that performs a task normally requiring human intelligence — this is a genuinely huge category, including things you've likely used without calling them "AI" at all: a spam filter, a recommendation engine, a spell-checker. Most of these are narrow, single-purpose, and don't reason about anything outside their one job.

Generative AI — Creates Content

Generative AI is a specific kind of AI that produces new content — text, code, images — based on a prompt. A large language model (LLM) like the ones powering ChatGPT or Claude is generative AI: you give it text, it generates more text.

Prompt: "Write a Playwright test that logs into ShopEasy and adds
         a product to the cart."

Generative AI response: [writes the actual test code]

This is genuinely useful — but notice what it didn't do: it didn't run the test, didn't check whether it passed, didn't look at the actual ShopEasy login page to confirm the locators it guessed at are even correct. It generated something and stopped. This is the single most important thing to understand about generative AI on its own: it produces an output, then waits for you.

AI Agents — Take Actions Toward a Goal

An AI agent adds something generative AI alone doesn't have: the ability to actually do things, observe the result, and decide what to do next — repeatedly, without you writing out each step.

Traditional generative AI: "Here's a test script." → stops, waits for you

AI agent: "My goal is to verify checkout works."
  → looks at the actual page
  → decides to click 'Add to Cart'
  → observes: a toast notification appeared confirming the item was added
  → decides to proceed to checkout
  → observes: a validation error blocks proceeding — "shipping address required"
  → decides to fill in the address field
  → tries checkout again
  → observes: success
  → reports: "Checkout works, but only after providing a shipping address —
     is that validation intentional?"

This is the genuinely new capability: an agent doesn't just generate a plan up front and blindly execute it — it reacts to what it actually observes at each step, the same way a human tester exploring an unfamiliar page would.

Agentic AI — The Broader System Built Around Agents

"Agentic AI" describes a system (or an entire approach) built around one or more AI agents operating with real autonomy toward a goal — not a single specific product, but a design philosophy. An "agentic QA system," concretely, is the combination of an AI agent, the tools it can call (browser control, API clients, a test runner), and the guardrails that keep it operating safely — all the pieces this course builds up across its remaining chapters.

Detailed Example — Locating ShopEasy's Actual Terminology

AI            → the entire field; includes a simple recommendation engine
                on ShopEasy's "You might also like" section

Generative AI → an LLM that, given a prompt, writes a Playwright test
                for ShopEasy's checkout flow — but doesn't run it

AI Agent      → a system that takes the goal "verify checkout works,"
                actually navigates ShopEasy, observes real page state,
                and decides what to try next based on what it sees

Agentic AI    → the overall QA system built around that agent — including
                the tools it can call, the guardrails on what it's allowed
                to do, and how its results get reported — which is exactly
                what this entire course teaches you to build

🧠 Think About It

Why might a generative-AI-only tool ("write me a test for X") be fundamentally limited for genuinely exploratory testing, no matter how good the underlying language model gets? Exploratory testing's entire value comes from reacting to what you actually find — a broken layout, an unexpected error, a validation rule you didn't know existed. A tool that only generates a plan up front, without ever looking at the real, current state of the application, can't discover anything it didn't already anticipate when writing the prompt.

⚠️ Common Mistake

Calling any AI-assisted testing tool "agentic" as a blanket marketing term. A tool that uses an LLM to suggest test cases from a requirements document is genuinely useful generative AI — but it isn't agentic unless it's actually taking actions, observing real results, and deciding what to do next based on those observations, autonomously.

💡 Quick Tip

A fast, practical test for "is this actually agentic": ask whether the tool can be legitimately surprised by something it observes and change its plan in response. If it always does exactly what a static script would have done, it's automation (possibly AI-generated automation) — not an agent.

Best Practices

  • Use the precise term for what a tool actually does — generative, agentic, or plain automation — rather than defaulting to "AI" for all three.
  • Evaluate a claimed "AI agent" by whether it genuinely reacts to real observations, not just by whether it uses an LLM somewhere internally.
  • Recognize that agentic AI is a system-level concept — the agent, its tools, and its guardrails together — not a single model or a single feature.

🎯 Key Takeaway

  • AI is the broad field; generative AI specifically produces content from a prompt and then stops.
  • An AI agent adds the loop that traditional generative AI lacks: act, observe the real result, decide what's next, repeat.
  • Agentic AI describes the overall system — agent, tools, and guardrails together — not a single product or model.

Interview Questions

A colleague says "we're using AI to write our tests" and describes a tool that takes a requirements doc and outputs Playwright test files, which a human then reviews and runs. Is this an AI agent? Walk through your reasoning.▾

No — this is generative AI, not an AI agent, even though it's genuinely useful. The defining test is whether the tool takes actions, observes real results, and decides what to do next based on those observations, on its own. Here, the tool produces an output (test files) and then stops — a human runs them, a human decides what happens if they fail. Nothing in this loop involves the tool itself observing a real result and reacting to it.

Generative AI (this example):
  requirements doc → LLM → test files → STOPS, human takes over

AI Agent (the distinguishing addition):
  goal → agent tries something → observes the REAL result →
  decides next step based on that observation → repeats

If the SAME tool were extended to actually run the tests it generated, look at which ones failed, investigate why, and either fix them or flag genuinely new bugs — that additional loop is what would make it agentic.

Your manager asks you to evaluate a new "AI-powered testing platform" for possible adoption. What specific question would you ask the vendor to determine whether their tool is genuinely agentic, or just generative AI with agentic-sounding marketing?▾

The single most revealing question: "Show me a case where the tool encountered something it didn't expect mid-task, and changed its plan in response, without a human intervening." A genuinely agentic tool should have a concrete, specific example — a locator that changed and the tool found the element a different way, an unexpected validation error the tool worked around or correctly reported as a real finding.

Vendor answer that's a RED FLAG (generative AI, not agentic):
"Our AI analyzes your requirements and generates comprehensive
test suites automatically." — describes ONE-TIME generation,
no mention of observing real results or adapting

Vendor answer that's genuinely agentic:
"During a checkout flow test, our agent's first attempt to click
'Continue' failed because the button was disabled pending a
required field. It examined the page, identified the required
field, filled it, and successfully completed the flow — then
flagged the disabled-button UX as worth human review."

The second answer describes an actual act-observe-decide loop reacting to something real and unanticipated — exactly the capability that distinguishes an agent from a generation tool, regardless of how either one is marketed.

Why does this course insist on the distinction between "AI-generated automation" and "agentic testing" rather than treating them as roughly the same thing?▾

Because they have genuinely different risk profiles, genuinely different value, and need genuinely different guardrails — treating them as interchangeable leads to real mistakes in how a team adopts either one.

AI-generated automation: an LLM writes a Playwright test once.
  Risk: a wrong locator guess, same as any human-written test
  mistake — reviewed once, then behaves exactly like ordinary
  deterministic automation forever after.

Agentic testing: an agent decides what to do at RUNTIME, every run.
  Risk: genuinely different runs could take genuinely different
  paths — which is exactly the point (adaptive, exploratory value)
  but also means the SAME safety review doesn't automatically
  carry over from one run to the next the way it does for a fixed
  script. This is why guardrails (covered later in this course)
  matter specifically for agentic systems in a way they simply
  don't for a one-time AI-generated test file.

Conflating the two leads to a real, common mistake: applying the "review once, trust forever" mental model appropriate for AI-generated static tests to a genuinely agentic system that makes new decisions every single run.

Give an example of something that's genuinely "AI" by the broad definition, but that virtually nobody would call agentic — and explain specifically what capability it's missing.▾

ShopEasy's "You might also like" product recommendation engine is a solid example. It's genuinely AI — it likely uses a trained model to predict which products a given user is statistically likely to be interested in based on browsing history.

What it does:
  user views Product A → model predicts → shows Products B, C, D

What it's missing for "agentic":
  - No goal it's actively pursuing beyond a single prediction
  - No sequence of actions it decides between
  - No observation-and-reaction loop — it makes one prediction
    and stops, exactly like the generative-AI example earlier,
    just without generating text specifically

It's a single-shot prediction system, structurally similar to the generative-AI pattern (produce an output, stop) even though it's not generating text — the missing ingredient in both cases is the same: no ongoing loop of actions, observations, and decisions toward a persistent goal.

Is an AI agent required to use a large language model internally? Why or why not?▾

Not strictly by the general definition of "agent" in computer science — the concept predates modern LLMs by decades, and plenty of older systems (a thermostat's control loop, a simple game AI) technically fit "observes its environment, decides an action, repeats." But in the specific, current context of "AI agents" as this course and the broader industry use the term, the reasoning and decision-making step is genuinely powered by an LLM — that's specifically what allows the agent to handle genuinely novel, unanticipated situations (an unfamiliar error message, an unexpected page layout) rather than only situations its original programmer explicitly coded a response for.

Older "agent" (rule-based): if error contains "required field" →
  fill nearest empty input — breaks on any error message the
  original programmer didn't specifically anticipate

Modern AI agent (LLM-based reasoning): reads the ACTUAL error
  text, reasons about what it likely means, decides a sensible
  next action — generalizes to error messages nobody explicitly
  programmed a response for

This is exactly why "AI agent" specifically (as opposed to just "agent") has become the common term recently — the LLM is what gives the decision-making step genuine flexibility for situations nobody explicitly anticipated in advance.
