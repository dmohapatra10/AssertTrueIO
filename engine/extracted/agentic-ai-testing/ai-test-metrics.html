AI Test Metrics

Prerequisites: LLM Evaluation and LLM-as-a-Judge

What is this?

A traditional test suite reports pass/fail counts — genuinely meaningful because each test has a definite, binary outcome. This chapter's evaluations produce SCORES across four dimensions, not binary results, and this final page is about what genuinely useful metrics look like for that.

Why a Pass Rate Alone Genuinely Doesn't Fit

❌ Forcing a binary "pass/fail" from a 1-5 dimension score:
  "Correctness >= 3 counts as PASS" — this THROWS AWAY real
  information. A response scoring 5/5 and one scoring 3/5 both
  count as identical "passes," despite being genuinely,
  meaningfully different in quality.

✅ Tracking the actual DISTRIBUTION of scores over time:
  Week 1: correctness scores across 50 test questions average
    4.2, with 3 responses scoring 2 or below
  Week 2: average drops to 3.8, with 9 responses scoring 2 or
    below — a genuine, real QUALITY REGRESSION, invisible to
    a binary pass/fail count if the THRESHOLD were still
    technically being "met" on average.

A Genuine Metrics Dashboard, Per Dimension

def compute_dimension_metrics(evaluation_results):
    from statistics import mean
    metrics = {}
    for dimension in ["relevance", "correctness", "groundedness", "consistency"]:
        scores = [r[dimension] for r in evaluation_results]
        metrics[dimension] = {
            "mean": round(mean(scores), 2),
            "min": min(scores),
            "below_threshold_count": sum(1 for s in scores if s < 3),
            "below_threshold_pct": round(
                sum(1 for s in scores if s < 3) / len(scores) * 100, 1),
        }
    return metrics
# A genuinely useful output — notice this preserves EXACTLY
# the per-dimension distinction Evaluation Dimensions argued for:
{
  "relevance":    {"mean": 4.6, "min": 3, "below_threshold_count": 0, ...},
  "correctness":  {"mean": 4.1, "min": 1, "below_threshold_count": 4, ...},
  "groundedness": {"mean": 3.2, "min": 1, "below_threshold_count": 11, ...},
  "consistency":  {"mean": 4.4, "min": 2, "below_threshold_count": 1, ...},
}
# GROUNDEDNESS specifically stands out — a lower mean AND far
# more below-threshold cases than the other three dimensions —
# EXACTLY the kind of dimension-specific signal a blended
# score would have hidden

🧠 Think About It

Why does tracking min and below_threshold_count alongside the mean matter, rather than reporting only the average score for each dimension? A high average can genuinely coexist with a small number of severely bad responses — Chapter 6's own principle about aggregate metrics hiding real patterns applies directly here. A mean of 4.1 for correctness sounds solid, but if 4 responses scored a genuine 1 (a serious, real failure), the average alone hides exactly the kind of severe, individual problem worth immediate attention, not just gradual quality tracking.

⚠️ Common Mistake

Reporting only a single, blended average across all four dimensions and all responses, collapsing exactly the distinctions this entire chapter has built up — per-dimension scores, and the shape of the distribution within each dimension, not just its center.

💡 Quick Tip

Tracking these metrics over TIME (as this page's opening example does, week over week) is genuinely more valuable than a single snapshot — a gradual decline in groundedness scores, even while still "acceptable" in absolute terms, is exactly the kind of trend Chapter 7's Anomaly and Trend Detection page taught you to watch for, now applied to LLM quality instead of performance metrics.

Best Practices

  • Track scores per dimension, never collapsed into one blended average across relevance, correctness, groundedness, and consistency.
  • Report the distribution — mean, minimum, and below-threshold count — not just a single average per dimension.
  • Track these metrics over time to catch gradual quality regressions, not just single-snapshot quality checks.

🎯 Key Takeaway

  • LLM feature quality needs distribution-based metrics per dimension, not a binary pass/fail count borrowed from traditional testing.
  • A high average score can hide a small number of severely bad individual responses — minimum and below-threshold counts catch what an average alone conceals.
  • Tracking these metrics over time, the same way Chapter 7 tracked performance trends, catches gradual quality regressions before they become severe.

Explain why below_threshold_count is tracked as BOTH a raw count and a percentage in this page's function, rather than just one or the other.▾

These serve genuinely different, complementary purposes — the raw count tells you the actual, absolute scale of the problem (how many real responses need attention), while the percentage tells you the RATE, which matters for comparing across periods with different total sample sizes.

Why the RAW COUNT matters:
"11 responses scored below threshold" is DIRECTLY actionable —
  it tells a reviewer EXACTLY how many INDIVIDUAL responses
  genuinely need to be looked at and potentially addressed,
  regardless of anything else.

Why the PERCENTAGE ALSO matters, separately:
If WEEK 1 had 50 total test questions and WEEK 2 had 200 (a
  larger test suite), comparing RAW COUNTS alone (say, 5 vs 15)
  might make week 2 look WORSE, when the PERCENTAGE (10% vs
  7.5%) actually shows a GENUINE IMPROVEMENT in the underlying
  RATE — the percentage controls for CHANGES in sample size
  that the raw count alone doesn't account for.

This is a genuinely practical, real consideration for metrics that might be computed across DIFFERENT-sized test runs over time — tracking BOTH the absolute count (for direct action) and the rate (for fair comparison across changing sample sizes) avoids misleading conclusions either measure alone could produce.

def compute_dimension_metrics(evaluation_results, thresholds=None):

                                  "consistency": 3}
    # ... uses thresholds[dimension] instead of the same
    # hardcoded 3 for every dimension ...
