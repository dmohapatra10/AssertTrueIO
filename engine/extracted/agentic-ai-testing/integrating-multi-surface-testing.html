Why does combining these four chapters' tools genuinely require Chapter 12's plan-verification techniques, when each chapter's own testing (Chapters 5, 6, 7 individually) never needed to check cross-surface plan soundness? 💡 Quick Tip

When first testing a multi-surface agent, deliberately using an objective that requires BOTH surfaces (like this page's checkout-and-confirmation example) — rather than an objective that happens to only need one — is a genuinely useful way to confirm the integration is actually working, not just that each tool set still functions independently.

How would you DESIGN a genuine TEST specifically to VERIFY the combined AGENT correctly HANDLES a scenario WHERE the browser and API STEPS genuinely DEPEND on each OTHER'S results (not JUST run INDEPENDENTLY)?▾

A GENUINELY useful test CONSTRUCTS an OBJECTIVE where the API STEP'S correct EXECUTION SPECIFICALLY requires DATA obtained FROM the browser STEP FIRST — DIRECTLY verifying GENUINE cross-surface DATA flow, not JUST two INDEPENDENT actions HAPPENING to occur in THE same run.

def test_cross_surface_data_dependency(agent, page):
    """Verifies the agent correctly passes information
    obtained via browser tools into a subsequent API call,
    rather than treating the two surfaces as independent."""
    agent.set_objective(
        "Complete checkout via the browser, note the resulting "
        "order confirmation number shown on screen, then verify "
        "via the API that THIS SPECIFIC order number shows the "
        "correct status."
    )
    report = agent.run(page)

    # A genuinely correct execution should show the API call's
    # PARAMETERS reflect the order number OBSERVED from the
    # browser step, not a hardcoded or guessed value
    api_call_step = next(
        s for s in report["full_history"]
        if s["action"]["name"] == "make_api_request"
    )
    browser_observed_order_number = extract_order_number_from_history(
        report["full_history"])
    return {
        "genuinely_used_observed_data": (
            browser_observed_order_number in
            str(api_call_step["action"]["input"])
        ),
    }

This DIRECTLY tests the GENUINELY hardest version of CROSS-surface integration — NOT just SEQUENCING two INDEPENDENT actions, but VERIFYING the AGENT correctly CARRIES information FROM one SURFACE into the OTHER, EXACTLY the KIND of rigorous, EVIDENCE-based verification Chapter 12'S OWN testing PHILOSOPHY (verify PROCESS, not JUST outcome) would RECOMMEND applying to THIS specific, genuinely NEW integration CAPABILITY.
