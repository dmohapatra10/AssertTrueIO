A Deliberate Note on This Chapter's Relationship to Chapter 6

Chapter 6 was explicit about its own scope: an agent exploring an API it doesn't have complete documentation for, discovering structure from real responses. This chapter starts from the opposite situation — a formal OpenAPI specification already exists — and asks a genuinely different question: given a complete, documented contract, how do you generate systematic, comprehensive coverage from it? It also covers territory Chapter 6 never touched at all: chaining several API calls into one real, multi-step workflow test.

Seven Focused Pages

  1. OpenAPI-Based Test Generation — systematically enumerating coverage from a formal spec
  2. Request Generation — building requests that genuinely satisfy the spec's own constraints
  3. API Test Data — data that respects types, formats, and enums the spec actually declares
  4. Schema and Response Validation — validating every response against its formal schema, systematically
  5. Negative API Testing — spec-driven negative coverage, not just a few hand-picked examples
  6. API Workflow Testing — genuinely new: chaining multiple calls into one coherent, real scenario
  7. Autonomous API Test Execution — comprehensive, spec-driven execution across many endpoints at once

The Running Example — Now With a Real Spec

Chapter 6 explored ShopEasy's orders API without documentation.
This chapter starts from its ACTUAL OpenAPI specification:

paths:
  /orders/{id}:
    get:
      parameters:
        - name: id
          in: path
          required: true
          schema: { type: integer }
      responses:
        '200':
          content:
            application/json:
              schema:
                type: object
                required: [id, status, total, items]
                properties:
                  id: { type: integer }
                  status: { type: string, enum: [pending, shipped, delivered, cancelled] }
                  total: { type: number }
                  items: { type: array }

Everything this chapter builds works FROM this formal contract — a genuinely different starting point than Chapter 6's discovery-from-nothing approach.

Common Mistakes to Watch For

  • Trusting the spec as automatically accurate — a documented contract can itself be stale, exactly the same risk Chapter 6's own Schema and Contract Analysis page raised.
  • Testing each endpoint only in isolation — this chapter's workflow-testing page exists specifically because real usage chains calls together.
  • Generating exhaustive coverage without any prioritization — comprehensive doesn't have to mean undifferentiated; Chapter 9's scoring lessons apply here too.
