Step-by-Step Implementation — Real Tool Definitions

// src/agent-tools.ts
import Anthropic from '@anthropic-ai/sdk';

export const BROWSER_TOOLS: Anthropic.Tool[] = [
  {
    name: 'navigate',
    description: 'Navigate the browser to a URL.',
    input_schema: {
      type: 'object',
      properties: { url: { type: 'string' } },
      required: ['url'],
    },
  },
  {
    name: 'click_element',
    description: 'Click an element by its accessible role and name.',
    input_schema: {
      type: 'object',
      properties: {
        role: { type: 'string' },
        name: { type: 'string' },
      },
      required: ['role', 'name'],
    },
  },
  {
    name: 'fill_field',
    description: 'Fill a form field identified by its label.',
    input_schema: {
      type: 'object',
      properties: {
        label: { type: 'string' },
        value: { type: 'string' },
      },
      required: ['label', 'value'],
    },
  },
  {
    name: 'report_objective_complete',
    description: 'Call this when the objective has genuinely been achieved.',
    input_schema: {
      type: 'object',
      properties: { summary: { type: 'string' } },
      required: ['summary'],
    },
  },
];

Code Explanation

Each tool's input_schema is real, enforced structure — the model literally cannot return a tool call missing a required field, a genuinely stronger guarantee than Chapter 3's approach of asking for JSON and hoping the shape matches. report_objective_complete is a deliberately special tool: it exists specifically so the model has an explicit, structured way to signal "I'm done," which this chapter's Evaluator page builds on directly.

Step-by-Step Implementation — Making a Real Tool Call

// src/call-with-tools.ts
import { anthropic } from './ai-client';
import { BROWSER_TOOLS } from './agent-tools';

export async function getNextToolCall(
  systemPrompt: string, conversationHistory: Anthropic.MessageParam[]
) {
  const response = await anthropic.messages.create({
    model: 'claude-sonnet-4-6',
    max_tokens: 1024,
    system: systemPrompt,
    tools: BROWSER_TOOLS,
    messages: conversationHistory,
  });

  const toolUse = response.content.find(
    (block): block is Anthropic.ToolUseBlock => block.type === 'tool_use'
  );
  if (!toolUse) {
    throw new Error('Expected a tool call but the model responded with text only.');
  }
  return { name: toolUse.name, input: toolUse.input, id: toolUse.id };
}

Why It Matters — A Genuinely Stronger Guarantee

Compare this to Chapter 3's generateScenarios, which asked for JSON in prose and then manually validated the shape after the fact. Here, input_schema is enforced by the API itself — a tool call for click_element is guaranteed to include both role and name before your code ever sees it. This doesn't eliminate the need for validation entirely (a role or name could still be wrong, just never structurally missing), but it closes off an entire category of malformed response this track has been defending against since Chapter 3.

Common Mistakes

  • Continuing to use JSON-in-prose prompting once real tool calling is available. This chapter's whole point is that tool calling provides a genuinely stronger structural guarantee — there's no reason to keep the weaker pattern once the agent architecture supports the real one.
  • Assuming tool calling eliminates all validation needs. It guarantees structural shape, not correctness of values — Chapter 3 and 6's validation disciplines still matter for what's inside a correctly-shaped tool call.

Best Practices

  • Define tool schemas with the same care you'd put into a function signature — required fields, clear types, and a description precise enough for the model to use correctly.
  • Include a dedicated "objective complete" tool explicitly, rather than trying to infer completion from ordinary conversational text.
