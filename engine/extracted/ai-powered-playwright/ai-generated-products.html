Introduction

The previous page's approach transfers directly here, with one real difference worth being explicit about: products need to feel coherent as a catalog, not just individually realistic — prices in a believable range for the category, names that sound like real products, not just varied words.

Step-by-Step Implementation

// src/generate-product-data.ts
import { askClaude } from './ai-client';

export interface GeneratedProduct {
  name: string;
  category: string;
  price: number;
  inStock: boolean;
  description: string;
}

export async function generateProducts(
  category: string, count: number
): Promise<GeneratedProduct[]> {
  const prompt = `Generate ${count} realistic products for an
e-commerce category: "${category}"

Prices should be believable for this category — not
suspiciously round numbers. Include a genuine mix of inStock
true and false. Product names should sound like real products
in this category, not generic placeholders.

Respond with ONLY valid JSON:
{"products": [{"name": string, "category": string,
"price": number, "inStock": boolean, "description": string}]}`;

  const raw = await askClaude(prompt);
  const parsed = JSON.parse(raw);
  if (!Array.isArray(parsed.products)) {
    throw new Error(`Expected {"products": [...]} but got: ${raw.slice(0, 200)}`);
  }
  return parsed.products;
}

Code Explanation

"Not suspiciously round numbers" is a small but genuinely useful instruction — $99.99 and $847.50 read as real prices; $100.00 and $500.00 repeated across every generated product reads as obviously synthetic, undermining the entire point of realistic test data.

Why It Matters — Testing Both Stock States Genuinely

ShopSmart's "Add to Cart" button should behave differently for in-stock versus out-of-stock products — this is exactly the kind of behavior three hardcoded, always-in-stock products would never exercise. Generating a genuine mix, as this page's prompt explicitly requests, is what makes both code paths actually testable without writing separate, manual fixtures for each state.

Common Mistakes

  • Not requesting a mix of stock states explicitly. Without it, generated products tend to default toward "in stock," leaving the out-of-stock path untested.
  • Accepting suspiciously round prices without noticing. These are a real, visible sign that generated data reads as synthetic — worth reviewing by eye before trusting a batch.

Best Practices

  • Request explicit state variety (stock status, price range) the same way the previous page requested demographic variety for users.
  • Spot-check generated prices for believability — a quick eye check catches the round-number problem immediately.

Hands-On Exercise

Generate products for two genuinely different ShopSmart categories — say, "Laptops" and "Phone Cases" — and compare the price ranges. Confirm they're believably different for each category, not the same generic range applied everywhere.

Key Takeaways

  • Product data needs its own, category-appropriate variety dimensions — believable pricing and a genuine mix of stock states, not just varied names.
  • A genuine mix of stock states is what makes both the in-stock and out-of-stock code paths actually testable.
  • The same generation discipline from the previous page — explicit variety requests — transfers directly, applied to a different real data shape.
