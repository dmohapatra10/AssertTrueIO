Running AI-Powered Tests in CI

Prerequisites: AI-Powered Playwright in CI/CD overview

What You'll Learn

Introduction

Chapter 3's requireEnv handled API keys locally, where a developer controls their own environment. CI introduces a genuinely different context — many runs, shared infrastructure, and logs a whole team can see.

Step-by-Step Implementation — A Real Workflow

# .github/workflows/ai-playwright-tests.yml
name: AI-Powered Playwright Tests

on:
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20

      - name: Install dependencies
        run: npm ci

      - name: Install Playwright browsers
        run: npx playwright install --with-deps chromium

      - name: Run Playwright tests
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: npx playwright test

      - name: Upload test results
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: playwright-report
          path: test-results/

Code Explanation

secrets.ANTHROPIC_API_KEY is the genuinely important line — GitHub Actions' secrets mechanism means the real key value never appears in logs, even if a step accidentally tries to print it. This is the CI-scale equivalent of Chapter 3's .gitignore discipline for local .env files — the same underlying principle, a different, real mechanism for a different, real environment.

Why It Matters — Cost at CI Scale Is Genuinely Different

LOCAL development: ONE developer, running tests OCCASIONALLY,
  genuinely LOW AI call volume

CI, at SCALE: EVERY pull request, potentially MULTIPLE times
  as commits get PUSHED, across an ENTIRE team — the SAME
  AI-powered TEST suite now runs FAR more often, and EVERY
  run genuinely COSTS money, not just TIME

This is exactly why Chapter 18's later cost-management chapter matters — a suite that felt affordable running occasionally during local development can become a real, meaningful cost once it's running on every single pull request across a real team's actual commit velocity.

Common Mistakes

  • Hardcoding an API key directly in the workflow file "just to test it quickly." This exposes the real key to anyone with read access to the repository — GitHub's secrets mechanism exists specifically to prevent this.
  • Running the full AI-powered suite on every single push without considering CI-scale cost. This page's comparison is worth taking seriously before wiring up a workflow this way — Chapter 16's later pages address smarter alternatives.

Best Practices

  • Always use your CI provider's real secrets mechanism for API keys — never hardcode them or pass them as plain workflow inputs.
  • Consider CI-scale cost explicitly before wiring an AI-powered suite to run on every push — this chapter's later pages on test selection and quality gates address this directly.
