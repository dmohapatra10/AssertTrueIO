Introduction — Aggregation, Not New Instrumentation

Chapter 18 logged real usage per call. Chapter 19 logged real actions per agent. Neither, alone, answers a genuinely different, real question: what is this entire system costing and doing, across every team, every week?

Step-by-Step Implementation — Aggregating What Already Exists

// src/system-wide-observability.ts
import { readFileSync } from 'fs';

interface UsageRecord { agentId: string; inputTokens: number; outputTokens: number; timestamp: string; }

export function aggregateUsageByAgent(
  usageLogPath: string
): Record<string, { totalCalls: number; totalTokens: number }> {
  const lines = readFileSync(usageLogPath, 'utf-8').split('\n').filter(Boolean);
  const records: UsageRecord[] = lines.map((l) => JSON.parse(l));

  const byAgent: Record<string, { totalCalls: number; totalTokens: number }> = {};
  for (const r of records) {
    if (!byAgent[r.agentId]) byAgent[r.agentId] = { totalCalls: 0, totalTokens: 0 };
    byAgent[r.agentId].totalCalls++;
    byAgent[r.agentId].totalTokens += r.inputTokens + r.outputTokens;
  }
  return byAgent;
}

Code Explanation

Notice this reads the exact same usage data Chapter 18's own logging already produces — nothing new is instrumented here. The real, new value is aggregation: turning many individual, per-call log lines into one genuine, organization-level picture, grouped by agent, ready for a real dashboard or weekly report.

Why It Matters — This Finding Is Only Visible in Aggregate

No single agent's own log would have revealed that exploration accounts for the majority of real system-wide cost — that pattern only becomes visible once every agent's usage is aggregated together. This is the genuine, real value observability adds beyond what Chapter 18 and Chapter 19's per-call and per-agent logging already provide individually.

Common Mistakes

  • Building separate, new instrumentation instead of aggregating existing logs. Chapter 18 and 19 already produce real, structured data — this page's whole point is reusing it, not duplicating collection effort.
  • Reviewing individual agent logs without ever aggregating across the whole system. This page's ShopSmart example shows real, actionable patterns that only appear once data from every agent is combined.

Best Practices

  • Build aggregation on top of Chapter 18 and 19's existing logging, rather than instrumenting new, separate collection.
  • Review system-wide aggregated usage regularly, not just individual agent logs in isolation — real patterns emerge only at that level.

Key Takeaways

  • System-wide observability aggregates data Chapter 18 and 19 already collect — it doesn't require new, separate instrumentation.
  • Real, actionable patterns — like which agent dominates system-wide cost — only become visible once individual logs are combined.
  • Regular review of aggregated, system-wide data is what turns individual logging into genuine organizational insight.
