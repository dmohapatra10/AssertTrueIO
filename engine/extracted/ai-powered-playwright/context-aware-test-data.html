Context-Aware Test Data

Prerequisites: Invalid and Boundary Test Data

What You'll Learn

  • Why individually valid fields can still combine into unrealistic data
  • Generating data that respects real relationships between fields
  • A concrete ShopSmart example where this genuinely matters

Introduction

Every earlier page in this chapter generated one field or one record type at a time. This page is about a subtler, real problem: a user with a valid email, a valid address, and a valid order total can still be nonsensical as a whole — a Denver ZIP code paired with a Miami city name, for instance, each individually well-formed, together clearly wrong.

Why It Matters — A Concrete ShopSmart Case

INDIVIDUALLY valid, but TOGETHER nonsensical:
  { city: "Denver", state: "CO", zip: "33139" }
  // "33139" is a REAL, validly-formatted ZIP — it's ALSO
  // Miami Beach's ZIP, not DENVER's. A field-by-field
  // VALIDATOR would accept this WITHOUT complaint.

GENUINELY coherent, context-aware:
  { city: "Denver", state: "CO", zip: "80203" }

Step-by-Step Implementation

// src/generate-context-aware-data.ts
import { askClaude } from './ai-client';

export interface CoherentAddress {
  street: string;
  city: string;
  state: string;
  zip: string;
}

export async function generateCoherentAddress(): Promise<CoherentAddress> {
  const prompt = `Generate ONE realistic US address where the
city, state, and ZIP code are GENUINELY consistent with each
other — a REAL ZIP code that actually corresponds to the
given city and state, not just a validly-formatted one.

Respond with ONLY valid JSON:
{"street": string, "city": string, "state": string, "zip": string}`;

  const raw = await askClaude(prompt);
  return JSON.parse(raw);
}

export async function generateCoherentOrder(
  productPrice: number, discountPercent: number
): Promise<{ subtotal: number; discount: number; total: number }> {
  const prompt = `Product price: $${productPrice}
Discount: ${discountPercent}%

Calculate the GENUINELY correct subtotal, discount amount, and
final total — these THREE numbers must be mathematically
CONSISTENT with each other, not just individually plausible.

Respond with ONLY valid JSON:
{"subtotal": number, "discount": number, "total": number}`;

  const raw = await askClaude(prompt);
  return JSON.parse(raw);
}

Code Explanation

Notice the prompt's explicit emphasis on consistency between fields, not just individual validity — this is the whole point of this page. generateCoherentOrder is a particularly concrete example: subtotal, discount, and total have an exact mathematical relationship, and a genuinely useful test fixture needs all three to actually agree, not just each look like a plausible dollar amount on its own.

Why It Matters — Catching a Real, Subtle Bug Class

A test using field-by-field-valid-but-incoherent data can pass even when ShopSmart's actual total calculation is subtly wrong, because the individually-generated numbers were never required to genuinely relate to each other. Context-aware data closes this gap — a test asserting the displayed total matches this page's calculated, consistent total will catch a real discount-calculation bug that isolated, unrelated field generation never would.

Common Mistakes

  • Generating each field of a record independently, in separate calls. This is exactly how the Denver ZIP code problem happens — nothing enforces consistency across genuinely separate generation calls.
  • Assuming "individually valid" is the same standard as "realistic." This page's whole point is that it genuinely isn't — coherence across fields is a separate, additional requirement.

Best Practices

  • Generate related fields together, in one call, whenever their values genuinely need to relate to each other — never split them across independent generation calls.
  • Explicitly state the consistency requirement in the prompt, the way this page's examples do — it doesn't happen by default.

Hands-On Exercise

Identify a set of related fields in your own application — a subtotal/tax/total triple, or a city/state/postal-code triple. Write a generation function following this page's pattern, explicitly requesting consistency, and verify a real, generated example by hand.

Key Takeaways

  • Individually valid fields can still combine into unrealistic, incoherent data — a genuinely separate concern from per-field validity.
  • Generating related fields together, in one call, with an explicit consistency requirement, is what actually produces coherent data.
  • Context-aware data catches a real class of bug — inconsistency between related values — that isolated, per-field generation can miss entirely.
