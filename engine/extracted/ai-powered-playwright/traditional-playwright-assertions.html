Introduction

No AI on this page, deliberately — the same choice Chapter 6 made with locator fundamentals. Before this chapter shows where AI genuinely helps with assertions, it's worth being clear about how strong Playwright's own assertion library already is on its own.

How It Works — The Core Assertion Methods

await expect(page.getByTestId('cart-total')).toHaveText('$49.98');
  // Exact TEXT match — genuinely correct or not, nothing fuzzy

await expect(page.getByRole('button', { name: 'Add to Cart' })).toBeVisible();
  // Exact VISIBILITY check

await expect(page).toHaveURL(/\/order-confirmed/);
  // Exact URL pattern match

await expect(page.getByTestId('cart-item')).toHaveCount(3);
  // Exact COUNT match

await expect(page.getByRole('button', { name: 'Add to Cart' })).toBeDisabled();
  // Exact STATE match

Why It Matters — Auto-Retry Is Already a Real Strength

Every one of these assertions auto-retries for a real, configurable timeout — Playwright doesn't check once and fail immediately if a value hasn't updated yet. This already solves a huge class of timing-related test flakiness, entirely without AI. It's worth being genuinely clear about this before layering anything else on top: reliability against timing issues was never the gap AI needs to fill.

Example — ShopSmart's Cart Total, Fully Deterministic

test('cart total updates after adding an item', async ({ page }) => {
  await page.goto('/products/probook-15');
  await page.getByRole('button', { name: 'Add to Cart' }).click();

  // Playwright RETRIES this check until the total updates, or
  // the timeout is reached — no AI needed, no judgment call,
  // exactly ONE correct value to match against
  await expect(page.getByTestId('cart-total')).toHaveText('$899.00');
});

Common Mistakes

  • Checking a value once with a manual read instead of an auto-retrying assertion. This reintroduces exactly the timing flakiness Playwright's own assertion library already solves.
  • Assuming this chapter exists because traditional assertions are somehow weak. They're genuinely strong for anything with one known, correct value — this chapter's real focus is the narrower cases where they're not the right tool.

Best Practices

  • Default to Playwright's own auto-retrying assertions for anything with a known, exact expected value.
  • Reach for the rest of this chapter's techniques only once you've confirmed a check genuinely has no single correct value — the next pages cover exactly how to recognize that.

Key Takeaways

  • Playwright's own assertion library is a genuinely strong, deterministic, auto-retrying foundation — not a gap AI needs to fill.
  • Every assertion on this page has exactly one correct answer, which is precisely why none of them need AI.
  • This chapter's remaining pages are about the narrower, genuinely different case where no single correct value exists to match against.
