Capturing Test Evidence

What You'll Learn

Introduction

This page builds the real, comprehensive capture this chapter's opening page argued for — every category Playwright can provide, assembled into one structured object the rest of this chapter's pages can work with.

Step-by-Step Implementation — Configuration

// playwright.config.ts
import { defineConfig } from '@playwright/test';

export default defineConfig({
  use: {
    screenshot: 'only-on-failure',
    video: 'retain-on-failure',
    trace: 'retain-on-failure',
  },
});

Step-by-Step Implementation — Assembling the Evidence Bundle

// src/capture-evidence.ts
import { Page, TestInfo } from '@playwright/test';

export interface EvidenceBundle {
  errorMessage: string;
  stackTrace: string;
  screenshotPath?: string;
  videoPath?: string;
  tracePath?: string;
  consoleLogs: string[];
  networkFailures: string[];
}

export function setupEvidenceCollection(page: Page) {
  const consoleLogs: string[] = [];
  const networkFailures: string[] = [];

  page.on('console', (msg) => {
    if (msg.type() === 'error') consoleLogs.push(msg.text());
  });
  page.on('requestfailed', (request) => {
    networkFailures.push(`${request.method()} ${request.url()} — ${request.failure()?.errorText}`);
  });

  return { consoleLogs, networkFailures };
}

export function buildEvidenceBundle(
  testInfo: TestInfo, consoleLogs: string[], networkFailures: string[]
): EvidenceBundle {
  const screenshot = testInfo.attachments.find((a) => a.name === 'screenshot');
  const video = testInfo.attachments.find((a) => a.name === 'video');
  const trace = testInfo.attachments.find((a) => a.name === 'trace');

  return {
    errorMessage: testInfo.error?.message ?? 'No error message captured',
    stackTrace: testInfo.error?.stack ?? 'No stack trace captured',
    screenshotPath: screenshot?.path,
    videoPath: video?.path,
    tracePath: trace?.path,
    consoleLogs,
    networkFailures,
  };
}

Code Explanation

Console logs and network failures need genuinely different handling than the rest — they're not available after the fact from testInfo alone. setupEvidenceCollection attaches listeners at the start of a test, actively accumulating evidence as the test runs, so it's available if the test later fails. This is a real, structural difference worth understanding: some evidence is captured passively by Playwright's config; some needs active collection during execution.

Example — Using This in a Real Test

import { test } from '@playwright/test';
import { setupEvidenceCollection, buildEvidenceBundle } from './capture-evidence';

test('checkout completes successfully', async ({ page }, testInfo) => {
  const { consoleLogs, networkFailures } = setupEvidenceCollection(page);

  // ... real test steps ...

  if (testInfo.status !== testInfo.expectedStatus) {
    const evidence = buildEvidenceBundle(testInfo, consoleLogs, networkFailures);
    // evidence is now a COMPLETE, structured bundle — ready
    // for this chapter's NEXT page to send to AI
  }
});

Common Mistakes

  • Only configuring screenshot and video, forgetting trace. The trace file is often the single richest piece of evidence — every action, every network request, a full timeline — skipping it discards real, valuable information.
  • Setting up console and network listeners only after a test has already failed. This evidence needs to be collected DURING execution — by the time a failure is detected, the moment to start listening has already passed.

Best Practices

  • Configure comprehensive capture (retain-on-failure) globally — it's cheap, and having evidence you don't end up needing costs far less than needing evidence you didn't capture.
  • Attach console and network listeners at the very start of every test, not conditionally based on whether you expect it might fail.

Hands-On Exercise

Add this page's evidence collection to one of your own real tests. Deliberately break it (change a locator to something invalid) and confirm every field in the resulting EvidenceBundle is genuinely populated — including console logs and network failures, not just the error message.

Key Takeaways

  • Playwright's config captures screenshots, video, and trace passively on failure — console logs and network activity need active listeners set up during the test itself.
  • Assembling everything into one structured EvidenceBundle is what makes this chapter's remaining pages able to work with evidence consistently, rather than reaching into testInfo differently each time.
  • Comprehensive capture is cheap and worth doing by default — the real cost decision, covered next, is what to actually send to AI.
