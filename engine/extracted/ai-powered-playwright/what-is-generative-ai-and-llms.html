What is Generative AI? What is an LLM?

Prerequisites: AI & LLM Basics for Playwright Engineers

What You'll Learn

  • A working definition of generative AI
  • What an LLM specifically is, and how it's different from traditional software
  • Why this distinction matters for how you'll use it in Playwright automation

Introduction

Generative AI is software that produces new content — text, code, an image — rather than only processing input through fixed, pre-written logic. An LLM (large language model) is the specific kind of generative AI this entire tutorial uses: a model trained on enormous amounts of text, capable of producing genuinely new text in response to whatever you send it, including test scenarios, Playwright code, and explanations of a failure.

Why It Matters

Ordinary Playwright code is deterministic — you wrote every line, and it does exactly what you told it to. An LLM is fundamentally different: you send it an instruction, and it generates a response based on patterns learned during training, not a lookup table you control. This isn't a minor technical detail — it's the reason Chapter 6's later validation steps exist at all, and it's why this chapter's final page treats "deterministic vs probabilistic" as a genuinely important, recurring distinction.

How It Works — A Concrete Comparison

ORDINARY CODE:
  function isValidEmail(email: string): boolean {
    return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email);
  }
  // The SAME input ALWAYS produces the SAME output — you
  // wrote every rule, and NOTHING about it can surprise you

AN LLM:
  "Is 'test@shopsmart.example.com' a valid-looking test email
  for ShopSmart's registration form?"
  // The MODEL generates a response based on PATTERNS learned
  // from training — genuinely useful, but NOT a rule YOU wrote
  // and verified line by line

Example — Sending ShopSmart's First Real Instruction

Later in this chapter, you'll send an LLM something like: "Generate test scenarios for ShopSmart's login form, covering valid credentials, an invalid password, and an empty email field." The model has never seen ShopSmart's actual login form — it generates scenarios based on patterns from countless login forms it learned from during training. That's genuinely useful, and it's also exactly why Chapter 3 insists on validating what comes back before trusting it.

Common Mistakes

  • Treating an LLM like a database lookup. It doesn't "know" ShopSmart's specific login form — it generates a plausible response based on general patterns, which is a genuinely different thing.
  • Assuming "generative" means "creative" in a vague, unhelpful sense. In this tutorial, generative specifically means "produces new, useful testing artifacts" — scenarios, code, analysis — not abstract creativity.

Best Practices

  • Keep the deterministic-vs-generative distinction in mind every time you read AI output in this tutorial — it's the single most useful mental model this chapter introduces.
  • Remember an LLM has no built-in knowledge of your specific application — everything it says about ShopSmart is inference, not memory.

Hands-On Exercise

Write down three things you'd want an LLM to help with in your own testing work. For each one, ask: is this something the model would need to GENERATE (a new scenario, new code) or something it would need to KNOW (a fact about my specific application)? Only the first category is something an LLM genuinely does well without extra help.

Key Takeaways

  • Generative AI produces new content; an LLM is the specific kind trained on text, used throughout this tutorial for scenarios, code, and analysis.
  • An LLM generates plausible responses from learned patterns — it has no built-in, verified knowledge of your specific application.
  • This distinction is why validation, covered starting in Chapter 3, is a genuine requirement, not an optional extra step.
