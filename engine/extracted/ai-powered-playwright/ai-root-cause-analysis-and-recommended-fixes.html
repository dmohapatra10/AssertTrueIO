Step-by-Step Implementation

// src/recommend-flaky-fix.ts
import { askClaude } from './ai-client';
import { FlakyClassification } from './diff-flaky-traces';

export interface FlakyFixRecommendation {
  recommendation: string;
  exampleCode: string;
}

const CAUSE_SPECIFIC_GUIDANCE: Record<string, string> = {
  'race-condition': 'Recommend an explicit wait for a specific condition (like waitForResponse or a specific locator state), never an arbitrary sleep.',
  'animation-timing': 'Recommend waiting for the element to be stable, using Playwright\\'s own actionability checks.',
  'network-variance': 'Recommend a longer, specific timeout for this exact request, not a blanket increase.',
  'test-order-dependence': 'Recommend explicit setup/teardown making the test independently runnable.',
  'shared-state': 'Recommend isolated, per-test data generation, referencing Chapter 8\\'s techniques.',
};

export async function recommendFix(
  classification: FlakyClassification, testCode: string
): Promise<FlakyFixRecommendation> {
  const guidance = CAUSE_SPECIFIC_GUIDANCE[classification.cause];

  const prompt = `Flaky cause: ${classification.cause}
Reasoning: ${classification.reasoning}
Cause-specific guidance: ${guidance}
Current test code: ${testCode}

Recommend a SPECIFIC fix following the guidance above. Include
a short code example showing the change.

Respond with ONLY valid JSON:
{"recommendation": string, "exampleCode": string}`;

  const raw = await askClaude(prompt);
  return JSON.parse(raw);
}

Code Explanation

CAUSE_SPECIFIC_GUIDANCE is the real, deliberate mechanism that prevents a generic, one-size-fits-all recommendation. Without it, a model asked simply "fix this flaky test" tends to suggest the same, familiar pattern — usually some kind of wait or retry — regardless of whether that's actually the right fix for this specific cause.

Common Mistakes

  • Asking for a fix without providing the cause-specific guidance. This is exactly what produces the generic "add a wait" recommendation regardless of the actual underlying cause.
  • Applying a network-variance fix (longer timeout) to a genuine race condition. A longer timeout might mask a race condition intermittently without fixing it — the cause-specific guidance exists to prevent exactly this kind of mismatched fix.

Best Practices

  • Always route a recommendation through cause-specific guidance — never ask for a generic fix to "flakiness" as an undifferentiated category.
  • Feed this chapter's recommendations into Chapter 11's self-healing pipeline, rather than applying them directly without validation.
