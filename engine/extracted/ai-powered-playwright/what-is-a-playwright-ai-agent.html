Introduction

This track has built genuine capability since Chapter 5 — planning, observation, exploration, healing. None of it was quite an "agent" in the full sense, because each piece lived in its own function, called individually. This page defines what actually changes once they're assembled.

How It Works — A Precise, Working Definition

An AGENT is:
  1. PERSISTENT — it maintains STATE across many steps, not
     just within ONE function call
  2. TOOL-using — it CHOOSES from a REAL set of available
     actions, via ACTUAL tool calling (Chapter 14'S own next
     page), not a hardcoded SEQUENCE of function calls
  3. OBJECTIVE-driven — it receives ONE, high-level GOAL and
     decides its OWN path toward it, DRAWING on planning
     (Ch5), exploration (Ch13), and RECOVERY (Ch6, Ch11) as
     NEEDED, not in a FIXED order

Why It Matters — What Chapter 5's Loop Was Missing

Chapter 5's runNaturalLanguagePlan was genuinely good — plan, validate, execute, observe, repeat. But it was still one function, called once, with no persistent memory beyond that single run, and no way to fall back to Chapter 6's healing or Chapter 13's exploration if something unexpected came up mid-run. A genuine agent needs all of this available as real, callable options within one, ongoing process — not separate functions a human decides between and calls manually.

Example — The Same Objective, Handled by a Real Agent

OBJECTIVE: "Verify ShopSmart's checkout completes correctly,
and report anything unexpected along the way."

A REAL agent, given THIS single objective, might GENUINELY:
  - PLAN a known sequence for the "verify checkout" PART
    (Chapter 5'S technique)
  - HEAL a broken locator it ENCOUNTERS mid-run (Chapter 6)
  - NOTICE an unexpected discount field and GENERATE a
    hypothesis about it (Chapter 13'S exploration)
  - ALL within ONE continuous run, choosing WHICH capability
    to draw on AS it goes — not through a human MANUALLY
    calling each earlier chapter's function in SEQUENCE

Common Mistakes

  • Treating any single function from earlier chapters as "the agent." Real agency requires persistence and choice among multiple real capabilities — a single function, however sophisticated, is still just one tool.
  • Assuming this chapter introduces new capabilities. Every real capability already exists — this page's whole point is that assembly itself is what creates something genuinely agent-like.

Best Practices

  • Keep this three-part definition — persistent, tool-using, objective-driven — as the test for whether something genuinely qualifies as an agent.
  • Revisit Chapters 5, 6, and 13 mentally as you read this chapter — recognizing where each piece fits is more valuable than reading this chapter's code as new material.

Key Takeaways

  • A genuine agent is persistent, tool-using, and objective-driven — three real, distinct properties, not just "uses AI."
  • Earlier chapters built genuine capabilities, but each lived in its own function — this chapter's assembly is what creates something agent-like.
  • The same objective, handled by a real agent, can draw on planning, healing, and exploration within one continuous run, rather than requiring a human to invoke each separately.
