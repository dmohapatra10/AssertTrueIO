Introduction

Chapter 9 trimmed evidence for one specific reason, in one specific context. This page generalizes that same real discipline into something applicable to every prompt this track has built.

How It Works — Three Real, Repeatable Techniques

1. TRIM verbose, unused CONTEXT — Chapter 9'S own lesson,
   generalized: don't send the FULL stack trace when the
   FIRST few frames genuinely suffice

2. AVOID repeating INSTRUCTIONS the model already SATISFIES
   reliably — if a JSON-shape instruction has NEVER produced
   a malformed RESPONSE in practice, extensive REPETITION of
   the SAME instruction adds tokens without adding real
   RELIABILITY

3. SUMMARIZE structured data instead of DUMPING it raw —
   Chapter 10'S OWN trace-analysis page already did this,
   stripping VERBOSE selector strings before sending a FULL
   action timeline

Example — A Real Before-and-After From Chapter 9's Own Code

// BEFORE (genuinely wasteful):
const prompt = `A Playwright test failed.

Here is the COMPLETE error message: ${payload.errorMessage}
Here is the COMPLETE stack trace, every single frame,
including deep framework internals: ${payload.fullStackTrace}
Here is the COMPLETE console log history for this ENTIRE
test run, every single message: ${JSON.stringify(payload.allConsoleLogs)}
...`;

// AFTER (Chapter 9'S actual, real approach):
const prompt = `A Playwright test failed.
Error: ${payload.errorMessage}
Relevant stack frames: ${payload.relevantStackFrames}
Recent console errors: ${JSON.stringify(payload.recentConsoleErrors)}
...`;

Why It Matters — This Isn't Just About Saving Money

A shorter, more focused prompt is often genuinely more reliable too — a model reasoning over a smaller, more relevant context has less irrelevant material to potentially get confused by. Trimming here isn't purely a cost optimization; it's frequently a quality improvement as well, the same real insight behind Chapter 9's original trimming decision.

Why It Matters — Shorter Isn't Automatically Better

Trimming too aggressively risks removing genuinely relevant context the model actually needs — Chapter 9's own relevantStackFrames keeps the first several frames specifically because that's usually where the real problem lives, not zero frames. The real skill is trimming what's genuinely irrelevant, not trimming for its own sake.

Common Mistakes

  • Sending complete, raw data "just in case it's needed." This page's before-and-after example shows the real cost of this instinct — most of that raw data goes unused for a typical case.
  • Trimming so aggressively that genuinely relevant context gets removed. This can make a prompt cheaper while making its actual output meaningfully worse — the real goal is relevance, not minimalism for its own sake.

Best Practices

  • Apply this page's three techniques to every prompt in your own project, using Chapter 9's own before-and-after as a concrete model.
  • Test trimmed prompts against real cases to confirm output quality holds — trimming that degrades results isn't genuinely optimization.

Key Takeaways

  • Chapter 9's evidence-trimming lesson generalizes into three real, repeatable techniques — trim unused context, avoid redundant instruction repetition, summarize rather than dump raw data.
