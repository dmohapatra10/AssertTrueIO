Introduction

The capstone's objective — verify checkout, report anything unexpected — is deliberately open-ended, the way Chapter 13's exploration objectives were. This page's job is turning it into something concrete enough to actually run.

Step-by-Step Implementation

// src/capstone-pipeline.ts (stage 1)
import { generateTestCases } from './generate-test-cases';
import { prioritizeByRisk } from './risk-based-generation';
import { convertToPlaywrightTests } from './convert-to-playwright';

export async function generateCapstonePlan(objective: string) {
  const testCases = await generateTestCases(
    'ShopSmart checkout flow, including discount code handling',
    'E-commerce checkout: cart review, discount application,
    shipping, payment, order confirmation'
  );

  const prioritized = prioritizeByRisk(testCases);
  const playwrightTests = await convertToPlaywrightTests(prioritized);

  return { testCases: prioritized, playwrightTests };
}

Code Explanation

Every function here is Chapter 4's own, called exactly as it was originally built — generateTestCases, prioritizeByRisk, convertToPlaywrightTests. Nothing about running inside this capstone changes their behavior; this stage's entire real contribution is calling them with the capstone's specific, real objective.

Why It Matters — Setting Up the Real Discovery

Notice none of Chapter 4's generated cases explicitly say "apply the same code twice" — that's precisely the point this track made back in Chapter 13: systematic generation, working from an explicit requirement, doesn't reliably think to test the specific case that reveals this particular bug. This stage's plan is genuinely solid, thorough coverage — and it's about to run into evidence during execution that points toward exactly the gap Chapter 13's exploration was built to fill.

Common Mistakes

  • Writing new generation logic specific to this capstone. Chapter 4's functions already exist, tested and explained — this stage is deliberately just a real, direct call into them.
  • Skipping risk-based prioritization. Without it, this chapter's capstone execution stage would run every generated case with equal priority, rather than genuinely focusing on checkout's real, higher-risk areas first.

Best Practices

  • Reuse Chapter 4's generation functions exactly as written — this stage's only real job is providing the capstone's specific, real context.
  • Keep the generated plan's output structure — both raw test cases and converted Playwright tests — since the next stage needs both.
