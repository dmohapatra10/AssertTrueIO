Validating the Candidate Fix

Prerequisites: Generating a Candidate Fix

What You'll Learn

  • Why a plausible-looking diff still needs to actually be run before anyone trusts it
  • Applying a patch to an isolated copy, never the real source file directly
  • What "validated" genuinely means at this stage — and what it doesn't yet mean

Introduction

The previous page's diff is readable and well-reasoned — it's still just a proposal nobody has actually run. This page closes that gap with real, empirical proof: does the originally-failing test genuinely pass with this patch applied?

Step-by-Step Implementation

// src/validate-candidate-patch.ts
import { execSync } from 'child_process';
import { copyFileSync, writeFileSync, readFileSync, mkdtempSync } from 'fs';
import { tmpdir } from 'os';
import { CandidatePatch } from './build-candidate-diff';

export interface ValidationResult {
  passed: boolean;
  output: string;
}

export function validatePatchInIsolation(
  patch: CandidatePatch, testName: string
): ValidationResult {
  // NEVER touch the REAL source file — copy it to an ISOLATED,
  // TEMPORARY location first
  const tempDir = mkdtempSync(`${tmpdir()}/patch-validation-`);
  const tempFilePath = `${tempDir}/${patch.filePath.split('/').pop()}`;
  copyFileSync(patch.filePath, tempFilePath);

  let content = readFileSync(tempFilePath, 'utf-8');
  for (const change of patch.changes) {
    content = content.replace(change.before.trim(), change.after.trim());
  }
  writeFileSync(tempFilePath, content, 'utf-8');

  try {
    const output = execSync(
      `npx playwright test ${tempFilePath} -g "${testName}"`,
      { encoding: 'utf-8' }
    );
    return { passed: true, output };
  } catch (error: any) {
    return { passed: false, output: error.stdout ?? String(error) };
  }
}

Code Explanation

The isolated temp directory is the genuinely important detail here — the real source file is never modified, even temporarily, during validation. This means a validation run that goes wrong, crashes, or produces an unexpected result never leaves the actual codebase in an inconsistent state, no matter what happens during the test execution itself.

Example — Validating ShopSmart's Locator Fix

const result = validatePatchInIsolation(patch, 'adds product to cart');

console.log(result.passed);
// true — the PATCHED version of the test, run in ISOLATION,
// GENUINELY passes against the real, current ShopSmart page

// If it DIDN'T pass, result.output contains the REAL Playwright
// failure output — genuinely useful for understanding WHY the
// candidate fix, despite LOOKING reasonable, didn't actually work

Why It Matters — What "Validated" Does and Doesn't Mean Yet

A passing result here proves the specific, originally-failing test now genuinely passes with this patch. It says nothing about whether the patch breaks something else in the suite — that's a real, separate question this chapter's next page addresses directly. Validation at this stage is necessary, not sufficient.

Common Mistakes

  • Applying the patch directly to the real source file "just to test it quickly." This page's isolated-copy approach exists specifically to prevent an in-progress validation from ever touching the actual codebase.
  • Treating a passing validation as proof the fix is safe to merge. It only proves the originally-failing test now passes — regression risk across the rest of the suite is still completely unaddressed at this point.

Best Practices

  • Always validate in an isolated copy, never the real file — no exceptions, even for a quick check.
  • Keep the full test output, not just a pass/fail boolean — it's genuinely useful if the patch doesn't work as expected.

Key Takeaways

  • A candidate patch needs to actually run, in isolation, before anyone trusts that it genuinely fixes the failing test.
  • Working in an isolated copy, never the real source file, means a failed or crashed validation never leaves the actual codebase inconsistent.
  • A passing validation here is necessary but not sufficient — it says nothing yet about regressions elsewhere in the suite, covered next.
