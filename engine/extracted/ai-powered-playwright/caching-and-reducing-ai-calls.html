Caching and Reducing AI Calls

Introduction — A Genuinely Different Cache Than Chapter 8's

Chapter 8 cached generated test data for reproducibility — the same data, reused deliberately across runs. This page caches something different: the result of an AI judgment call, reused specifically when the same real input would produce the same real answer.

Step-by-Step Implementation

// src/cache-ai-results.ts
import { createHash } from 'crypto';
import { readFileSync, writeFileSync, existsSync } from 'fs';

const CACHE_PATH = 'test-data/ai-result-cache.json';

function hashInput(input: string): string {
  return createHash('sha256').update(input).digest('hex');
}

export function getCachedOrCompute<T>(
  cacheKeyInput: string, compute: () => Promise<T>
): Promise<T> {
  const cache: Record<string, T> = existsSync(CACHE_PATH)
    ? JSON.parse(readFileSync(CACHE_PATH, 'utf-8'))
    : {};

  const key = hashInput(cacheKeyInput);
  if (key in cache) {
    return Promise.resolve(cache[key]);
  }

  return compute().then((result) => {
    cache[key] = result;
    writeFileSync(CACHE_PATH, JSON.stringify(cache, null, 2), 'utf-8');
    return result;
  });
}

Code Explanation

The cache key is a hash of the actual input — meaning the cache is only ever reused when the exact same evidence produces the exact same classification request, never a stale answer applied to genuinely different evidence. This is the real, important guard against the risk this technique introduces: a wrong or outdated cached result being silently reused.

Example — Caching Chapter 9's Classification, Concretely

import { classifyFailure } from './classify-failure';
import { getCachedOrCompute } from './cache-ai-results';

async function classifyWithCache(payload: AnalysisPayload) {
  const cacheKeyInput = JSON.stringify(payload);
  return getCachedOrCompute(cacheKeyInput, () => classifyFailure(payload));
}

Why It Matters — Recognizing When the Cheapest Call Is No Call

A flaky test failing the same way repeatedly, before Chapter 12's healing gets applied, is a real, concrete case where this cache genuinely helps — the same evidence, classified identically each time, doesn't need a fresh AI call for every single occurrence. This is a real cost reduction that costs nothing in accuracy, since the cache key guarantees identical input before ever reusing a result.

Common Mistakes

  • Caching based on a loose or partial key, like just the test name. This risks returning a stale classification for genuinely different evidence — the hash-of-full-input approach this page uses exists specifically to prevent this.
  • Caching results that should never be reused, like exploratory hypothesis generation. Chapter 13's exploration deliberately wants genuine variety across runs — caching there would defeat its actual purpose.

Best Practices

  • Cache based on a hash of the complete, real input — never a partial key that could collide across genuinely different cases.
  • Reserve caching for calls where identical input should genuinely produce identical, reusable output — not for calls that deliberately want variety, like exploration.

Key Takeaways

  • This caches AI judgment results for identical input — genuinely different from Chapter 8's deliberate test-data reproducibility cache.
  • A full-input hash as the cache key is what prevents a stale result from being silently reused for genuinely different evidence.
  • Not every call should be cached — calls that deliberately want variety, like Chapter 13's exploration, are the wrong fit for this technique.
