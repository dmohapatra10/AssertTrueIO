Introduction

The previous stage produced a real, executable plan. This stage runs it — and because the capstone's actual objective is "report anything unexpected," not just "run these specific cases," this stage does something the plan alone wouldn't: exploring beyond it.

Step-by-Step Implementation

// src/capstone-pipeline.ts (stage 2)
import { executeAction } from './map-to-playwright';
import { setupEvidenceCollection, buildEvidenceBundle } from './capture-evidence';
import { chooseNextExploration } from './exploration-strategy';
import { Page, TestInfo } from '@playwright/test';

export async function executeCapstonePlan(
  playwrightTests: any[], page: Page, testInfo: TestInfo
) {
  const { consoleLogs, networkFailures } = setupEvidenceCollection(page);
  const results = [];

  // RUN the generated plan (Chapter 5's execution)
  for (const test of playwrightTests) {
    const outcome = await executeAction(test.action, page);
    results.push({ test, outcome });
  }

  // THEN, because the REAL objective is open-ended (Chapter
  // 13), explore ONE step beyond the fixed plan:
  const exploration = await chooseNextExploration(
    'checkout flow, discount handling', await observeForExploration(page), []
  );
  const explorationOutcome = await executeAction(exploration.action, page);
  results.push({ test: exploration, outcome: explorationOutcome });

  const evidence = buildEvidenceBundle(testInfo, consoleLogs, networkFailures);
  return { results, evidence };
}

Code Explanation

The plan-execution loop and the single exploration step are both real, unchanged calls into Chapter 5 and Chapter 13's own functions. Running just one real exploration step beyond the fixed plan is deliberate — it's exactly this kind of extra step that let Chapter 13's original agent stumble onto the discount-code field nobody explicitly planned for.

Why It Matters

This is the real, concrete moment this capstone's fixed plan and its open-ended exploration genuinely diverge in outcome — the plan alone would have reported clean success, missing the bug entirely. Combining Chapter 5's systematic execution with even one real Chapter 13-style exploration step is what actually surfaces it here, in this continuous run.

Common Mistakes

  • Running only the fixed, generated plan, skipping exploration entirely. This page's own example shows exactly what would be missed — the plan alone reports clean, misleading success.
  • Forgetting to set up Chapter 9's evidence collection before execution begins. Console and network listeners need to be active during the run, not added afterward, or this stage's evidence bundle would be incomplete.

Best Practices

  • Combine systematic plan execution with at least some real exploration whenever an objective is genuinely open-ended, following this page's own pattern.
  • Always set up evidence collection before execution starts, using Chapter 9's own established discipline.
