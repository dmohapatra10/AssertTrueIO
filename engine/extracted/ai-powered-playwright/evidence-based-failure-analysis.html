Step-by-Step Implementation

// src/complete-failure-analysis.ts
import { buildEvidenceBundle } from './capture-evidence';
import { selectEvidenceForAnalysis } from './select-evidence-for-analysis';
import { classifyFailure } from './classify-failure';
import { analyzeRootCause } from './root-cause-analysis';
import { askClaude } from './ai-client';
import { TestInfo } from '@playwright/test';

export interface CompleteAnalysis {
  failure: string;
  rootCause: string;
  evidence: string;
  confidence: 'high' | 'medium' | 'low';
  recommendedAction: string;
}

export async function analyzeFailureCompletely(
  testInfo: TestInfo, consoleLogs: string[], networkFailures: string[]
): Promise<CompleteAnalysis> {
  const bundle = buildEvidenceBundle(testInfo, consoleLogs, networkFailures);
  const payload = selectEvidenceForAnalysis(bundle);
  const classification = await classifyFailure(payload);
  const rootCause = await analyzeRootCause(payload, classification);

  const confidencePrompt = `Given this analysis:
Category: ${classification.category}
Root cause: ${rootCause.likelyCause}
Supporting evidence: ${rootCause.supportingEvidence}
Alternatives considered: ${JSON.stringify(rootCause.alternativeExplanations)}

Rate confidence (high, medium, low) based on how DIRECTLY the
evidence supports this conclusion. Recommend ONE specific,
concrete next action.

Respond with ONLY valid JSON:
{"confidence": "high" | "medium" | "low", "recommendedAction": string}`;

  const raw = await askClaude(confidencePrompt);
  const { confidence, recommendedAction } = JSON.parse(raw);

  return {
    failure: payload.errorMessage,
    rootCause: rootCause.likelyCause,
    evidence: rootCause.supportingEvidence,
    confidence,
    recommendedAction,
  };
}

Code Explanation

Confidence is deliberately assessed as its own, separate step — after classification and root cause are already established, not bundled into the earlier calls. This mirrors Chapter 7's own discipline for judgment calls: a confidence rating that considers the completed reasoning is more honest than one produced alongside it, where the model might overstate certainty before fully working through alternatives.

Why It Matters — Confidence Changes What Happens Next

A high-confidence "Application Defect" classification might reasonably auto-file a bug report. A low-confidence one should route to a human for review first — the same finding, treated with meaningfully different urgency and autonomy based on how directly the evidence actually supports it. This is exactly why confidence is a first-class part of this structure, not an afterthought.

Common Mistakes

  • Treating every analysis, regardless of confidence, identically. A low-confidence result deserves more human scrutiny before acting on it — this chapter's next page's reports should make confidence visible, not bury it.
  • Making recommendedAction generic ("investigate further"). A genuinely useful recommendation is specific and actionable, the way this page's example points to a concrete next step.

Best Practices

  • Assess confidence as a distinct step, after the reasoning is complete, not bundled into the classification or root cause calls.
  • Make recommended actions concrete and specific enough that a human could act on them without further investigation.
