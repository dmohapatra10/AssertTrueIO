Introduction — Why Chapter 5's Observation Isn't Quite Enough Here

Chapter 5's observePage was scoped tightly to what one specific, known next step needed — product names for "select a product," nothing more. Exploration has no known next step to scope around; it needs to see genuinely everything worth considering, since the strategy layer from the previous page needs real options to choose between.

Step-by-Step Implementation

// src/observe-for-exploration.ts
import { Page } from '@playwright/test';

export interface ExplorationObservation {
  url: string;
  interactiveElements: { role: string; name: string }[];
  formFields: { label: string; type: string }[];
  visibleText: string[];
}

export async function observeForExploration(
  page: Page
): Promise<ExplorationObservation> {
  const buttons = await page.getByRole('button').all();
  const links = await page.getByRole('link').all();

  const interactiveElements = await Promise.all(
    [...buttons, ...links].map(async (el) => ({
      role: await el.getAttribute('role') ?? 'button',
      name: (await el.textContent()) ?? '',
    }))
  );

  const inputs = await page.locator('input, select, textarea').all();
  const formFields = await Promise.all(
    inputs.map(async (el) => ({
      label: (await el.getAttribute('aria-label')) ?? (await el.getAttribute('name')) ?? '',
      type: (await el.getAttribute('type')) ?? 'text',
    }))
  );

  const visibleText = (await page.locator('h1, h2, h3').allTextContents());

  return { url: page.url(), interactiveElements, formFields, visibleText };
}

Code Explanation

This captures every button, link, and form field — genuinely broader than Chapter 5's product-name-only scope, since exploration doesn't know in advance which of these will matter. It's still not "capture everything" in the Chapter 9 sense — full HTML, every attribute — this is a deliberate middle ground, broad enough for genuine choice, not so broad it becomes noisy or expensive.

Why It Matters

This observation is exactly what the previous page's strategy function needs to make a genuinely informed choice — it can see the discount code field exists at all, which is what made the "apply it twice" hypothesis from this chapter's opening page possible in the first place. Chapter 5's narrower observation would never have surfaced this field, since it wasn't relevant to that chapter's specific, known next step.

Common Mistakes

  • Reusing Chapter 5's scoped observation unchanged for exploration. It would miss exactly the kind of genuinely unexpected element — like a discount field nobody explicitly asked about — that makes exploration valuable at all.
  • Capturing the full page HTML "to be thorough." This reintroduces the token-cost problem Chapter 9 already addressed — broad but bounded capture, not everything.

Best Practices

  • Scope exploration observation to interactive elements and structure — broad enough for genuine choice, bounded enough to stay affordable.
  • Re-observe after every single action during exploration, since the whole point is discovering things that weren't anticipated in advance.
