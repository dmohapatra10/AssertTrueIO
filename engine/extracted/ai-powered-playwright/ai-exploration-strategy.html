Introduction

Without real structure, an exploring agent can easily click the same button repeatedly, or drift toward whatever seems most interesting in the moment while leaving genuinely unexplored areas untouched. This page builds the strategy layer that prevents that.

Step-by-Step Implementation

// src/exploration-strategy.ts
import { askClaude } from './ai-client';
import { PageObservation } from './observe-page';

export interface ExploredArea {
  pageUrl: string;
  actionsAttempted: string[];
}

export interface NextExplorationChoice {
  action: string;
  target: string;
  reasoning: string;
}

export async function chooseNextExploration(
  objective: string, currentObservation: PageObservation,
  alreadyExplored: ExploredArea[]
): Promise<NextExplorationChoice> {
  const prompt = `Exploration objective: "${objective}"

Current page: ${JSON.stringify(currentObservation)}
Already explored (do NOT simply repeat these):
${JSON.stringify(alreadyExplored)}

Choose ONE next action that explores something GENUINELY new
relative to what's already been tried — not a minor variation.

Respond with ONLY valid JSON:
{"action": string, "target": string, "reasoning": string}`;

  const raw = await askClaude(prompt);
  return JSON.parse(raw);
}

Code Explanation

alreadyExplored is the genuinely important addition beyond Chapter 5's simpler loop — without real memory of what's been tried, an agent has no way to recognize it's repeating itself. The prompt's explicit instruction against "minor variation" matters too: trying getByRole('button', {name: 'Checkout'}) and then a nearly-identical variant isn't genuine new exploration, even though it's technically a different action.

// Step 1: nothing explored yet

{ action: "click", target: "Apply discount code twice in succession",
  reasoning: "The discount field and single-application flow are

// Step 9, exploration BROADENING to a different page:
{ action: "navigate", target: "Order history page",

  checking whether an incomplete order appears here is a new area" }

Why It Matters — Real Spread, Not Just Real Depth

Notice the third example choosing to navigate somewhere entirely different, rather than continuing to probe checkout more narrowly. Good exploration strategy balances depth (trying several variations on one area) against spread (moving to genuinely different areas once one seems well-covered) — tracking alreadyExplored explicitly is what makes this balance possible to reason about at all.

Common Mistakes

  • Not tracking already-explored areas at all. Without this, an agent has no way to recognize repetition, and exploration can circle the same few actions indefinitely.
  • Only ever going deeper, never broader. An agent that only refines its current area misses genuinely different, unexplored parts of the application entirely.

Best Practices

  • Always pass the full history of already-explored areas into each new choice — this is what makes each decision genuinely informed, not memoryless.
  • Periodically favor broadening to a new area once a specific one has been reasonably well covered, rather than exploring only ever deeper.

Key Takeaways

  • Choosing what to explore next requires genuine memory of what's already been tried — without it, repetition is difficult to avoid.
  • Good exploration balances depth and spread, using the explored-areas history to decide when each is appropriate.
  • This strategy layer is what turns open-ended freedom into productive, non-repetitive exploration, rather than aimless wandering.
