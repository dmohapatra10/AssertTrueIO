Introduction

Step-by-Step Implementation — The Original Four, Reusing Chapter 14 Directly

// src/register-playwright-tools.ts
import { z } from 'zod';
import { server } from './mcp-server';
import { executeAgentTool } from './agent-execute';
import { Page } from '@playwright/test';

export function registerBrowserTools(page: Page) {
  server.registerTool('navigate',
    { description: 'Navigate the browser to a URL.',
      inputSchema: { url: z.string() } },
    async ({ url }) => ({
      content: [{ type: 'text', text: await executeAgentTool('navigate', { url }, page) }],
    })
  );

  server.registerTool('click_element',
    { description: 'Click an element by its accessible role and name.',
      inputSchema: { role: z.string(), name: z.string() } },
    async ({ role, name }) => ({
      content: [{ type: 'text', text: await executeAgentTool('click_element', { role, name }, page) }],
    })
  );

  server.registerTool('fill_field',
    { description: 'Fill a form field identified by its label.',
      inputSchema: { label: z.string(), value: z.string() } },
    async ({ label, value }) => ({
      content: [{ type: 'text', text: await executeAgentTool('fill_field', { label, value }, page) }],
    })
  );
}

Code Explanation

Every one of these three tool handlers is a thin wrapper — the actual work happens in executeAgentTool, Chapter 14's own function, completely unchanged. This confirms the pattern this chapter has followed throughout: MCP adds a standardized way to reach these tools, without touching what the tools themselves actually do.

Step-by-Step Implementation — Four Genuinely New Tools

server.registerTool('read_page',
  { description: 'Get a structured summary of the current page.',
    inputSchema: {} },
  async () => {
    const observation = await observeForExploration(page);
    return { content: [{ type: 'text', text: JSON.stringify(observation) }] };
  }
);

server.registerTool('screenshot',
  { description: 'Capture a screenshot of the current page state.',
    inputSchema: {} },
  async () => {
    const buffer = await page.screenshot();
    return { content: [{ type: 'image', data: buffer.toString('base64'), mimeType: 'image/png' }] };
  }
);

server.registerTool('run_test',
  { description: 'Run a named Playwright test file and return whether it passed.',
    inputSchema: { testFile: z.string() } },
  async ({ testFile }) => {
    const result = validatePatchInIsolation(
      { filePath: testFile, changes: [] }, testFile
    );
    return { content: [{ type: 'text', text: JSON.stringify(result) }] };
  }
);

server.registerTool('read_trace',
  { description: 'Extract the action timeline from a trace file.',
    inputSchema: { tracePath: z.string() } },
  async ({ tracePath }) => {
    const actions = extractTraceActions(tracePath);
    return { content: [{ type: 'text', text: JSON.stringify(actions) }] };
  }
);

Why It Matters — These Four Are Also Entirely Reused

read_page reuses Chapter 13's observeForExploration. run_test reuses Chapter 11's validatePatchInIsolation. read_trace reuses Chapter 10's extractTraceActions. Not one line of genuinely new testing logic appears anywhere on this page — every tool is a thin MCP wrapper around a function this track already built and explained in full.

Common Mistakes

  • Reimplementing tool logic inside the MCP handler instead of calling existing functions. Every handler on this page is a thin wrapper for a real reason — duplicating logic here would create two places needing the same maintenance going forward.
  • Forgetting get_test_result as a genuinely separate concern from run_test. Running a test and later retrieving a specific prior result are different operations — worth their own distinct tool, following this same registration pattern.

Best Practices

  • Every new MCP tool should wrap an existing, already-tested function — write genuinely new logic only when no earlier chapter's function already covers the need.
  • Keep tool descriptions precise and specific — they're what a model actually reads to decide which tool fits a given moment.
