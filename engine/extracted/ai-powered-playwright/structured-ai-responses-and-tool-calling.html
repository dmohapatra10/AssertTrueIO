Structured AI Responses and Tool Calling

Prerequisites: Prompts and Context

What You'll Learn

Introduction

A chatbot answering in free-form prose is fine for a conversation. It's a genuine problem for automation — your code needs to reliably parse what came back, and prose is not reliably parseable. Structured responses and tool calling are the two mechanisms this entire tutorial depends on to turn AI output into something Playwright code can actually use.

How It Works — Free-Form vs Structured

FREE-FORM (hard to reliably parse):
  "Sure! I think you should test the login form with a few
  scenarios. First, try a valid login. Then maybe an invalid
  password. You could also check what happens with an empty
  email field."

STRUCTURED (reliably parseable):
  {
    "scenarios": [
      { "name": "valid login", "email": "test@shopsmart.example.com",
        "password": "correct-password", "expected": "success" },
      { "name": "invalid password", "email": "test@shopsmart.example.com",
        "password": "wrong-password", "expected": "error shown" },
      { "name": "empty email", "email": "",
        "password": "correct-password", "expected": "validation error" }
    ]
  }

The structured version is what Chapter 3's code actually loops over to generate Playwright tests. The free-form version would need fragile, unreliable text parsing to extract the same information.

How It Works — Tool Calling

TOOL CALLING lets an LLM say "call THIS specific function,
with THESE specific parameters" INSTEAD of just generating
text describing what it WOULD do.

Defined tool: click_element(role: string, name: string)

Model's response, given the objective "log in to ShopSmart":
  NOT: "I would click the login button"
  INSTEAD: a structured tool call —
    { "tool": "click_element", "input": { "role": "button",
      "name": "Log In" } }

Your CODE receives this and ACTUALLY calls Playwright's
click, using the model's chosen parameters — this is EXACTLY
the mechanism Chapter 14's AI agent is built on.

Why It Matters

Tool calling is what separates an AI agent that can genuinely interact with ShopSmart's real browser from a chatbot that can only describe what it would do. Every agent this tutorial builds — from the locator healer in Chapter 6 through the full exploratory agent in Chapter 13 — depends on tool calling to translate the model's reasoning into real, executable Playwright actions.

Common Mistakes

  • Building automation around parsing free-form text output. This is fragile by nature — a slightly different phrasing breaks your parser. Structured output exists specifically to avoid this.
  • Confusing "the model described an action" with "the action actually happened." Tool calling is what makes the model's choice something your code actually executes — a free-form description alone does nothing.

Best Practices

  • Request structured output whenever a response needs to be reliably consumed by code, not just read by a human.
  • Define tools with clear, specific parameters — the same care you'd put into designing any function signature.

Take this page's free-form login-scenario example and rewrite it as structured JSON, following the pattern shown. Then sketch, in plain language, what a fill_field(label: string, value: string) tool call would look like for filling ShopSmart's email field with a test address.

Key Takeaways

  • Structured responses are reliably parseable by code; free-form prose is not — this distinction matters for anything automation-facing.
  • Tool calling lets a model choose a specific action with specific parameters, which your code then actually executes.
  • Every AI agent this tutorial builds, starting in Chapter 14, depends on tool calling as its core mechanism.
