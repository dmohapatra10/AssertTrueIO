Identifying the Failed Step

Prerequisites: Screenshot and Network Analysis

What You'll Learn

  • Finding the exact failing action deterministically, before reaching for AI
  • Why this specific question rarely needs AI reasoning at all
  • Handling the genuinely ambiguous case, where more than one action shows a problem

Introduction — Applying Chapter 5's Core Rule Here

"Which action failed" sounds like it might need judgment, especially across a long sequence. It usually doesn't — this page applies Chapter 5's own exact-versus-judgment rule directly: an action either has a recorded error or it doesn't, which is a deterministic check, not a reasoning task.

Step-by-Step Implementation — The Deterministic Case

// src/find-failed-action.ts
import { TraceAction } from './extract-trace-data';

export function findFailedAction(actions: TraceAction[]): {
  index: number; action: TraceAction
} | null {
  const failedIndex = actions.findIndex((a) => a.error);
  if (failedIndex === -1) return null;
  return { index: failedIndex, action: actions[failedIndex] };
}

Code Explanation

This is deliberately simple, plain code — no AI call anywhere in it. A trace action either has an error field populated or it doesn't; finding the first one that does is an exact operation with one correct answer, exactly like Chapter 5's locator-to-Playwright mapping. Reaching for AI here would add cost and latency for a question that's already fully answered by the data itself.

Example — Finding the Failure in ShopSmart's Timeline

const result = findFailedAction(actions);

// { index: 3, action: { type: "waitForSelector", ...,
//   error: "Timeout 30000ms exceeded" } }
// EXACTLY the ONE action with a recorded error — no reasoning
// needed, just a REAL, deterministic search

Why It Matters — The Genuinely Ambiguous Case

Sometimes more than one action shows a problem — a network request failed early, and a later action also recorded a timeout. Here, "which one actually caused the failure" genuinely is a judgment call, since the deterministic search alone can't say whether the early network failure caused the later timeout, or whether they're unrelated. This is exactly where this chapter's earlier, sequence-aware AI analysis earns its place.

Step-by-Step Implementation — The Genuinely Ambiguous Case

import { askClaude } from './ai-client';

export async function resolveAmbiguousFailurePoint(
  actions: TraceAction[], candidateIndices: number[]
): Promise<{ primaryFailureIndex: number; reasoning: string }> {
  const prompt = `Multiple actions in this sequence show
problems, at indices: ${candidateIndices.join(', ')}
Full sequence: ${JSON.stringify(actions)}

Determine which is the GENUINE, primary point of failure —
the others may be DOWNSTREAM consequences, not independent
causes. Explain your reasoning.

Respond with ONLY valid JSON:
{"primaryFailureIndex": number, "reasoning": string}`;

  const raw = await askClaude(prompt);
  return JSON.parse(raw);
}

Common Mistakes

  • Using AI to find the failed action even in the simple, single-failure case. This is exactly the kind of exact, deterministic question that doesn't need it — Chapter 5's rule applies directly.
  • Treating every action with a recorded issue as an independent, equally-likely cause. This page's ambiguous case exists because later problems are often downstream consequences of an earlier one, not separate failures.

Best Practices

  • Always try the deterministic search first — reach for AI reasoning only when genuinely more than one candidate exists.
  • When resolving ambiguity, explicitly ask the model to consider which candidates might be downstream consequences, not just list them as equally likely.

Hands-On Exercise

Run findFailedAction against several real traces from your own project. For any case where it returns a result, confirm this deterministic approach was sufficient — then construct or find a genuinely ambiguous case with multiple candidate failures, and run resolveAmbiguousFailurePoint against it.

Key Takeaways

  • Finding the single failed action in a sequence is usually a deterministic search, not a task needing AI judgment — the same rule Chapter 5 established for locator mapping.
  • Genuine ambiguity arises specifically when multiple actions show problems, where AI reasoning about downstream consequences earns a real place.
  • Trying the deterministic approach first, and reaching for AI only when it's genuinely insufficient, keeps this step both fast and honest about when reasoning is actually needed.
