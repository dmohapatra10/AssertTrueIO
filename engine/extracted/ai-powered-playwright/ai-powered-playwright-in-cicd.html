Why This Chapter Is Genuinely Different

Every earlier chapter in this track ran its own code locally, or against a single, direct browser session. CI introduces real, new constraints — genuine cost at scale, secrets that must never leak into logs, and a team of people who see results whether or not anyone was watching the run happen. This chapter takes techniques this track already built and puts them where a real team actually encounters them.

Common Mistakes

  • Treating CI as just "running the same tests somewhere else." This chapter's opening page is explicit about the genuinely new constraints CI introduces — cost, secrets, and scale chief among them.
  • Forgetting that Chapter 11's human-approval rule still applies in CI. This chapter's closing page addresses this directly — automation in a pipeline is not an exception to that rule, it's exactly where the rule matters most.

Best Practices

  • Read this chapter in order — later pages assume the CI configuration and cost discipline the earlier pages establish.
  • Keep this track's earlier chapters open for reference — every technique here reuses a function this track already built and explained.

Key Takeaways

  • This chapter applies this track's existing techniques inside a real CI pipeline, rather than introducing fundamentally new testing capability.
  • CI introduces genuine new constraints — cost at scale, secret handling, and team-wide visibility — that shape how these techniques get deployed.
  • Chapter 11's human-approval rule for any code change carries into CI unchanged — automation there is not an exception to it.
