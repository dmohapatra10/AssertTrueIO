Step-by-Step Implementation — Extracting Timeline Screenshots

// src/extract-trace-screenshots.ts
import AdmZip from 'adm-zip';

export interface TimelineScreenshot {
  actionIndex: number;
  imagePath: string;
}

export function extractScreenshots(
  traceZipPath: string, outputDir: string
): TimelineScreenshot[] {
  const zip = new AdmZip(traceZipPath);
  const screenshots: TimelineScreenshot[] = [];

  const entries = zip.getEntries().filter((e) =>
    e.entryName.startsWith('resources/') && e.entryName.endsWith('.jpeg')
  );

  entries.forEach((entry, i) => {
    const outputPath = `${outputDir}/step-${i}.jpeg`;
    zip.extractEntryTo(entry, outputDir, false, true, false, `step-${i}.jpeg`);
    screenshots.push({ actionIndex: i, imagePath: outputPath });
  });

  return screenshots;
}

Step-by-Step Implementation — Extracting the Full Network Log

// src/extract-trace-network.ts
import AdmZip from 'adm-zip';

export interface NetworkEvent {
  url: string;
  method: string;
  status?: number;
  failed: boolean;
  timestamp: number;
}

export function extractNetworkEvents(traceZipPath: string): NetworkEvent[] {
  const zip = new AdmZip(traceZipPath);
  const networkEntry = zip.getEntry('trace.network');
  if (!networkEntry) return [];

  const lines = zip.readAsText(networkEntry).split('\n').filter(Boolean);
  return lines.map((line) => {
    const event = JSON.parse(line);
    return {
      url: event.url,
      method: event.method,
      status: event.status,
      failed: !event.status || event.status >= 400,
      timestamp: event.timestamp,
    };
  });
}

Why It Matters — Correlating Network Failures With Actions

function correlateNetworkWithActions(
  actions: TraceAction[], networkEvents: NetworkEvent[]
) {
  return actions.map((action) => ({
    ...action,
    concurrentFailures: networkEvents.filter(
      (n) => n.failed && Math.abs(n.timestamp - action.timestamp) < 500
    ),
  }));
}

Common Mistakes

  • Only looking at the final screenshot, ignoring earlier ones in the timeline. An earlier screenshot showing an unexpected modal or loading state often explains a later failure more directly than the final image alone.
  • Treating network and action data as unrelated evidence. This page's correlation function shows real, genuine value in connecting them — a failed request near a specific action is a strong, concrete lead.

Best Practices

  • Extract screenshots across the whole timeline when investigating a genuinely confusing failure, not just the final one.
  • Correlate network failures with nearby actions by timestamp — this connection is often more informative than either evidence source alone.

Hands-On Exercise

Run extractNetworkEvents against a real trace and use correlateNetworkWithActions to check whether any action in your timeline had a concurrent network failure. If one exists, investigate whether it's genuinely related to your test's actual failure.

Key Takeaways

  • A trace's screenshots span the whole timeline, not just the failure moment — genuinely more than Chapter 9's single capture.
  • The full network log, extracted from trace.network, goes beyond Chapter 9's live-listener sample of recent failures.
  • Correlating network events with nearby actions by timestamp often reveals connections neither evidence source shows clearly on its own.
