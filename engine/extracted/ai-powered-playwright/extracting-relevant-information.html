Introduction

Chapter 9's tracePath was a link to a file — this page is about actually opening it programmatically. Everything from this chapter's remaining pages depends on the structured timeline this page produces.

Step-by-Step Implementation

// src/extract-trace-data.ts
import AdmZip from 'adm-zip';

export interface TraceAction {
  type: string;
  selector?: string;
  timestamp: number;
  durationMs: number;
  error?: string;
}

export function extractTraceActions(traceZipPath: string): TraceAction[] {
  const zip = new AdmZip(traceZipPath);
  const traceEntry = zip.getEntry('trace.trace');
  if (!traceEntry) {
    throw new Error(`No trace.trace file found in ${traceZipPath}`);
  }

  const lines = zip.readAsText(traceEntry).split('\n').filter(Boolean);
  const actions: TraceAction[] = [];

  for (const line of lines) {
    const event = JSON.parse(line);
    if (event.type === 'action') {
      actions.push({
        type: event.method,
        selector: event.params?.selector,
        timestamp: event.startTime,
        durationMs: event.endTime - event.startTime,
        error: event.error?.message,
      });
    }
  }

  return actions;
}

Code Explanation

The trace file's real, internal format is a JSONL stream — one JSON object per line — which is why this reads line by line rather than parsing the whole thing as one JSON document. Filtering for event.type === 'action' matters too: a real trace file contains several kinds of events (actions, network requests, console messages), and this function deliberately extracts only the action timeline, leaving network and console extraction to their own, focused functions on a later page.

Why It Matters

This structured array is genuinely more useful than a raw JSONL dump — it's exactly the shape this chapter's remaining pages need to reason about sequence, timing, and where a failure occurred. Notice the last action's durationMs: 30000 and its error — this single field already hints strongly at a timeout, information a plain error message alone wouldn't make this immediately visible or easy to compare against the actions before it.

Common Mistakes

  • Trying to parse the entire trace.trace file as one JSON document. It's JSONL — newline-delimited, one object per line — parsing it as a single document will fail immediately.
  • Extracting every event type into one undifferentiated list. Actions, network requests, and console messages are genuinely different concerns — this page deliberately extracts only actions, leaving the others to their own focused functions.

Best Practices

  • Keep extraction functions focused on one event type each, the way this page separates actions from network and console data.
  • Preserve timing information (timestamp, durationMs) explicitly — it's what makes later pages' sequence and duration analysis possible.

Hands-On Exercise

Run this page's function against a real trace file from your own project. Review the extracted actions by eye and identify, just from the timing data, whether any single action took meaningfully longer than the others around it.

Key Takeaways

  • A trace file's real internal format is JSONL — parsed line by line, not as a single JSON document.
  • Extracting actions into a structured, typed array is the genuine foundation the rest of this chapter builds on.
  • Timing data alone, once extracted, already surfaces real signal — like an unusually long duration hinting at a timeout — before any AI analysis even happens.
