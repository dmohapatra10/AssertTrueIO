Introduction

This page turns Chapter 2's abstract "structured responses" concept into real, working code — sending the requirement "Test the login functionality of ShopSmart," and getting back scenarios your code can genuinely loop over, not prose you'd need to parse by hand.

Step-by-Step Implementation

// src/generate-scenarios.ts
import { askClaude } from './ai-client';

export interface TestScenario {
  name: string;
  email: string;
  password: string;
  expected: string;
}

export async function generateScenarios(
  requirement: string
): Promise<TestScenario[]> {
  const prompt = `Given this requirement: "${requirement}"

Generate test scenarios for ShopSmart's login form. Respond
with ONLY valid JSON, no other text, in exactly this shape:

{"scenarios": [{"name": string, "email": string,
"password": string, "expected": string}]}

Include at least one valid-login scenario, one invalid-password
scenario, and one empty-field scenario.`;

  const raw = await askClaude(prompt);
  const parsed = JSON.parse(raw);

  if (!Array.isArray(parsed.scenarios)) {
    throw new Error(
      `Expected {"scenarios": [...]} but got: ${raw.slice(0, 200)}`
    );
  }
  return parsed.scenarios;
}

Code Explanation

Two things here matter beyond the happy path. The prompt explicitly says "respond with ONLY valid JSON, no other text" — without this, models often add a friendly sentence before or after the JSON, which breaks JSON.parse. And the response is checked for the expected shape (scenarios must genuinely be an array) before returning it — exactly Chapter 2's warning about missing context applied concretely: if the model didn't get clear enough instructions, this check catches it immediately, with a useful error, rather than failing confusingly three steps later.

Common Mistakes

  • Calling JSON.parse without a try/catch or shape validation. If the model adds any stray text, JSON.parse throws — and even when it parses successfully, the shape still needs checking, since valid JSON in the wrong shape is just as unusable.
  • Not asking explicitly for "ONLY valid JSON, no other text." This single instruction meaningfully reduces the chance of a response you can't parse at all.

Best Practices

  • Always validate a parsed response's actual shape, not just that JSON.parse succeeded without throwing.
  • Include a real slice of the raw response in any error message — it's often the fastest way to see what actually went wrong.

Hands-On Exercise

Run this page's code yourself. Then deliberately remove the "respond with ONLY valid JSON" instruction from the prompt and run it again — see whether JSON.parse now fails, and notice how much that one instruction was actually doing.

Key Takeaways

  • Explicit formatting instructions in the prompt meaningfully reduce parsing failures — this isn't a minor nicety.
  • Shape validation after parsing catches malformed responses with a useful, specific error, rather than a confusing failure downstream.
