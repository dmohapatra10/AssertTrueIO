Generating Playwright Code from Scenarios

Prerequisites: From Prompt to Structured Test Scenarios

What You'll Learn

  • Turning structured scenarios into real, executable Playwright TypeScript code
  • Providing the model with the actual page structure it needs, rather than letting it guess
  • Writing generated code to a real file, ready for the next page's validation and execution

Introduction

The previous page produced structured data — genuinely useful, but not yet a test. This page closes that gap: given a scenario and ShopSmart's real login page structure, generate an actual Playwright test file.

Step-by-Step Implementation

// src/generate-tests.ts
import { askClaude } from './ai-client';
import { TestScenario } from './generate-scenarios';
import { writeFileSync } from 'fs';

// Real, known page structure — given EXPLICITLY, never guessed,
// per this chapter's system prompt from Creating the AI Client
const LOGIN_PAGE_STRUCTURE = `
Login page real locators:
  Email field: page.getByLabel('Email')
  Password field: page.getByLabel('Password')
  Submit button: page.getByRole('button', { name: 'Log In' })
  Error message: page.getByRole('alert')
  Success redirect target: page with URL containing '/dashboard'
`;

export async function generateTestCode(
  scenario: TestScenario
): Promise<string> {
  const prompt = `Generate a single Playwright test in TypeScript
for this scenario: ${JSON.stringify(scenario)}

Use ONLY these real, known locators — never invent a selector:
${LOGIN_PAGE_STRUCTURE}

Respond with ONLY the TypeScript code, no explanation, no
markdown code fences. The test must import { test, expect }
from '@playwright/test' and use async/await correctly.`;

  return askClaude(prompt);
}

export async function generateAndSaveTest(
  scenario: TestScenario,
  filePath: string
): Promise<void> {
  const code = await generateTestCode(scenario);
  writeFileSync(filePath, code, 'utf-8');
}

Code Explanation

LOGIN_PAGE_STRUCTURE is the single most important part of this page. Chapter 1 was explicit that a hallucinated locator sounds exactly as confident as a correct one — giving the model ShopSmart's real, actual locators, and instructing it to "never invent a selector," is what prevents the exact failure mode that page warned about. Without this, the model would generate plausible-sounding, wrong selectors, using patterns from other login forms it learned from during training.

Expected Result

// src/try-generate-test.ts
import { generateScenarios } from './generate-scenarios';
import { generateAndSaveTest } from './generate-tests';

async function main() {
  const scenarios = await generateScenarios(
    'Test the login functionality of ShopSmart'
  );
  await generateAndSaveTest(
    scenarios[0], 'tests/generated/login-valid.spec.ts'
  );
}
main();

Common Mistakes

  • Not providing the real page structure at all. Without LOGIN_PAGE_STRUCTURE, the model has no genuine information about ShopSmart's actual locators — it would generate plausible guesses instead, exactly Chapter 1's hallucination warning made concrete.
  • Writing generated code straight to tests/ where Playwright's runner picks it up automatically. This chapter's next page is explicit about why generated code needs review before it runs — tests/generated/ keeps it separated until then.

Best Practices

  • Always provide real, known page structure explicitly — never rely on the model's general training knowledge for your specific application's actual selectors.
  • Keep AI-generated test files in a clearly separate folder until they've been validated, the subject of this chapter's final page.

Hands-On Exercise

Run this page's code for all three scenarios from the previous page, not just the first one. Open each generated file and check, by eye, whether every locator matches LOGIN_PAGE_STRUCTURE exactly — this is the exact manual check the next page turns into an automated one.

Key Takeaways

  • Providing real, explicit page structure — not letting the model guess — is what prevents hallucinated selectors from reaching generated code.
  • Generated code belongs in a separate folder until validated, not directly where Playwright's runner will pick it up automatically.
