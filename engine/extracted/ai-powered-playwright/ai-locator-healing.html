Step-by-Step Implementation

// src/heal-locator.ts
import { Page } from '@playwright/test';
import { generateLocatorCandidates } from './generate-locator-candidates';
import { rankLocatorCandidates } from './rank-locator-candidates';
import { findFirstValidCandidate } from './validate-locator-candidate';

export interface HealResult {
  healed: boolean;
  workingLocatorCode?: string;
  reason?: string;
}

export async function healLocator(
  brokenLocatorDescription: string, page: Page
): Promise<HealResult> {
  // Broken Locator → AI Analysis → Candidate Locators
  const candidates = await generateLocatorCandidates(
    brokenLocatorDescription, page
  );
  if (candidates.length === 0) {
    return { healed: false, reason: 'No candidates generated' };
  }

  // Candidate Locators → (ranking, deterministic)
  const ranked = rankLocatorCandidates(candidates);

  // → Validation → Best Candidate
  const result = await findFirstValidCandidate(ranked, page);
  if (!result) {
    return { healed: false, reason: 'No candidate validated on the real page' };
  }

  // → Test Execution (the CALLER'S responsibility, not this
  // function's — healing SUGGESTS a working locator, it does
  // NOT modify test files automatically)
  return { healed: true, workingLocatorCode: result.candidate.locatorCode };
}

Code Explanation

Every function this code calls was built on this chapter's earlier pages — nothing new here except the assembly itself. Notice the comment at the end: healLocator deliberately stops at returning a working locator. It does not rewrite a test file automatically — that's a much bigger, riskier decision this tutorial's Chapter 11 addresses directly, with its own explicit human-approval step.

Why It Matters — What Happens Next Is a Deliberate Choice

A healed locator is genuinely useful information — but what to do with it is a real decision, not something this function makes on your behalf. Logging it for a human to review and update manually is one option; Chapter 11's self-healing chapter covers a more automated path, with its own genuine safeguards. This chapter deliberately stops short of deciding that for you.

Common Mistakes

  • Having healLocator automatically rewrite the source test file. This chapter's function deliberately doesn't — that's a meaningfully bigger decision Chapter 11 handles with its own explicit approval step.
  • Running this pipeline only after a test has already failed in CI, with no human ever reviewing the healed result. A healed locator is a suggestion worth a human's attention, not an automatic, unreviewed fix.

Best Practices

  • Log every healing result — including reason on failure — the same observability discipline Chapter 5 established for ambiguous instruction resolution.
  • Treat a successful heal as a prompt for human review, not a silent, automatic fix, until you've deliberately built the additional safeguards Chapter 11 covers.
