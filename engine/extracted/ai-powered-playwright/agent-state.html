Introduction

Chapter 14's opening page named persistence as one of three properties a genuine agent needs. This page builds it for real — a single, structured object that survives across every step of a run, not scattered local variables inside one function.

Step-by-Step Implementation

// src/agent-state.ts
import Anthropic from '@anthropic-ai/sdk';
import { ExploredArea } from './exploration-strategy';
import { EvidenceBundle } from './capture-evidence';

export interface AgentState {
  objective: string;
  conversationHistory: Anthropic.MessageParam[];
  exploredAreas: ExploredArea[];
  collectedEvidence: EvidenceBundle[];
  stepCount: number;
  startTime: number;
  objectiveComplete: boolean;
}

export function createInitialState(objective: string): AgentState {
  return {
    objective,
    conversationHistory: [{ role: 'user', content: objective }],
    exploredAreas: [],
    collectedEvidence: [],
    stepCount: 0,
    startTime: Date.now(),
    objectiveComplete: false,
  };
}

Code Explanation

Every field here is reused directly from an earlier chapter's own type — exploredAreas from Chapter 13, collectedEvidence from Chapter 9 — assembled into one coherent object rather than living as separate parameters passed manually between function calls. conversationHistory is genuinely new to this chapter: it's what lets tool calling maintain real context across many steps, the actual mechanism the previous page's tool calls depend on.

Example — State Evolving Across Real Steps

let state = createInitialState(
  'Verify checkout completes correctly, report anything unexpected.'
);

// AFTER step 1 (navigate):
state.stepCount = 1;
state.conversationHistory.push(
  { role: 'assistant', content: [toolUseBlock] },
  { role: 'user', content: [toolResultBlock] }
);

// AFTER discovering an unexpected discount field mid-run:
state.exploredAreas.push({
  pageUrl: 'https://shopsmart.example.com/cart',
  actionsAttempted: ['observed discount field'],
});

// The SAME state object carries ALL of this forward into
// EVERY subsequent step's reasoning

Why It Matters

Without this single, persistent object, the agent's tool calls would have no real memory of earlier steps — every call would need the full context re-explained, and Chapter 13's exploration strategy (which depends on knowing what's already been explored) simply wouldn't work across multiple, separate calls. This state object is what makes "continuous run," not "sequence of unrelated calls," an accurate description of what's happening.

Common Mistakes

  • Passing state pieces as separate function parameters instead of one coherent object. This makes it easy to forget updating one piece (like exploredAreas) while updating another, leading to state that's subtly inconsistent with itself.
  • Not appending to conversationHistory after every tool call and result. Without this, the model loses real context about what it already tried, risking exactly the repetition Chapter 13's strategy page worked to prevent.

Best Practices

  • Keep all agent state in one object, updated consistently after every step — never split across separate, independently-managed variables.
  • Append every tool call and its result to conversationHistory immediately, so the model's next reasoning step has complete, accurate context.
