How It Works — Tokens, Concretely

A TOKEN is roughly 3-4 CHARACTERS of English text — NOT a
word, NOT a character. "checkout" is ONE token. "unexpectedly"
is genuinely TWO or three.

EVERY real API response includes ACTUAL usage numbers:
{
  usage: {
    input_tokens: 1204,
    output_tokens: 187
  }
}

THIS is the REAL, ground-truth number — not an estimate, the
EXACT count the call actually used, EVERY time.

Step-by-Step Implementation — Measuring Your Own Real Usage

// src/measure-token-usage.ts
import { anthropic } from './ai-client';

export async function callAndLogUsage(prompt: string) {
  const response = await anthropic.messages.create({
    model: 'claude-sonnet-4-6',
    max_tokens: 500,
    messages: [{ role: 'user', content: prompt }],
  });

  console.log(`Input: ${response.usage.input_tokens} tokens, ` +
    `Output: ${response.usage.output_tokens} tokens`);

  return response;
}

Common Mistakes

  • Assuming every AI call costs roughly the same. A short classification call and a multi-step sequential analysis pipeline are genuinely different in both latency and token usage — treating them as equivalent leads to real, avoidable surprises.
  • Estimating token usage instead of reading it from the actual response. The API returns exact, real numbers every time — there's no reason to guess when ground truth is already available in response.usage.

Best Practices

  • Log real usage numbers from response.usage during development, so cost decisions are grounded in actual data, not assumptions.
  • Think in relative terms — which call types in your own suite are genuinely heavier than others — rather than memorizing specific dollar amounts that will go stale.

Key Takeaways

  • A token is roughly 3-4 characters, and every real API response includes exact, ground-truth usage numbers — no need to estimate.
  • Relative latency differences between call types — simple mapping, classification, multi-step analysis, vision — are durable even as absolute pricing and speed change over time.
  • Measuring real usage directly from your own calls is more reliable than assuming or memorizing figures that go stale.
