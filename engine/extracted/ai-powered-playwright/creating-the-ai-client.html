Introduction

Chapter 2 introduced the system prompt as standing behavior for an entire session. This page builds it for real — one module, imported everywhere this tutorial needs to talk to the model, so every later chapter's code shares the same consistent behavior.

Step-by-Step Implementation

// src/ai-client.ts
import Anthropic from '@anthropic-ai/sdk';
import { config } from './config';

export const anthropic = new Anthropic({
  apiKey: config.anthropicApiKey,
});

export const SHOPSMART_SYSTEM_PROMPT = `You are a QA testing
assistant helping test ShopSmart, a realistic e-commerce
application with login, registration, product search and
filtering, product details, cart management, checkout, payment
simulation, order history, and user profile features.

Always respond with valid, well-formed content in the exact
format requested. Never invent details about ShopSmart's actual
implementation that weren't explicitly provided to you. When
generating Playwright code, use only locators and page structure
that were explicitly given — never guess at a selector.`;

export async function askClaude(userPrompt: string): Promise<string> {
  const message = await anthropic.messages.create({
    model: 'claude-sonnet-4-6',
    max_tokens: 1024,
    system: SHOPSMART_SYSTEM_PROMPT,
    messages: [{ role: 'user', content: userPrompt }],
  });

  const textBlock = message.content.find(
    (block) => block.type === 'text'
  );
  if (!textBlock || textBlock.type !== 'text') {
    throw new Error('Expected a text response but got none.');
  }
  return textBlock.text;
}

Code Explanation

Two design choices here matter beyond just working code. First, SHOPSMART_SYSTEM_PROMPT explicitly says "never invent details" and "never guess at a selector" — a direct, concrete application of Chapter 1's honest treatment of hallucination risk, baked into every single call this client makes. Second, askClaude returns a plain string, but does real work first: it checks the response actually contains a text block before returning it, rather than assuming the shape blindly.

Common Mistakes

  • Creating a new Anthropic client instance in every file that needs one. This module exists specifically so there's one client, one system prompt, used consistently everywhere.
  • Assuming message.content[0] is always a text block. A real response can contain other block types — this page's explicit check is what makes the function's return type genuinely trustworthy, not just usually correct.

Best Practices

  • Put hallucination-reducing instructions directly in the system prompt, where they apply to every call automatically, rather than repeating them in each individual request.
  • Validate the shape of an AI response before using it, the same way you'd validate any external API's response.

Key Takeaways

  • One AI client module, imported everywhere, keeps behavior consistent across this entire tutorial's later code.
  • The system prompt is where hallucination-reducing instructions genuinely belong — applied automatically to every call, not repeated per request.
  • Validating a response's actual shape before using it is the same discipline you'd apply to any external API, not something unique to AI.
