Step-by-Step Implementation — Generating a Testable Hypothesis

// src/generate-hypothesis.ts
import { askClaude } from './ai-client';
import { ExplorationObservation } from './observe-for-exploration';

export interface Hypothesis {
  description: string;
  testSteps: string[];
  expectedIfHealthy: string;
}

export async function generateHypothesis(
  observation: ExplorationObservation, objective: string
): Promise<Hypothesis> {
  const prompt = `Exploration objective: "${objective}"
Current page: ${JSON.stringify(observation)}

Generate ONE specific, testable hypothesis about POTENTIAL
unexpected behavior — not a vague concern, a concrete thing
to actually TRY. State what a HEALTHY application should do
if the hypothesis DOESN'T reveal a problem.

Respond with ONLY valid JSON:
{"description": string, "testSteps": [string, ...],
"expectedIfHealthy": string}`;

  const raw = await askClaude(prompt);
  return JSON.parse(raw);
}

Code Explanation

expectedIfHealthy is the genuinely important field here — without a stated expectation for the healthy case, there's no clear way to tell whether the hypothesis actually revealed something wrong or just... happened. This mirrors Chapter 4's own negative-test discipline: knowing what correct, safe behavior looks like is what makes an unexpected result actually recognizable as unexpected.

Step-by-Step Implementation — Testing the Hypothesis and Evaluating the Result

import { buildEvidenceBundle } from './capture-evidence';

export interface DiscoveryResult {
  hypothesis: Hypothesis;
  actualOutcome: string;
  revealsIssue: boolean;
  reasoning: string;
}

export async function testHypothesis(
  hypothesis: Hypothesis, page: Page
): Promise<DiscoveryResult> {
  // Execute the hypothesis's steps against the REAL page —
  // reusing Chapter 5's action-execution approach
  for (const step of hypothesis.testSteps) {
    // (mapped to real Playwright actions, per Chapter 5)
  }

  const actualOutcome = await page.locator('body').textContent() ?? '';

  const evalPrompt = `Hypothesis: ${hypothesis.description}
Expected if healthy: ${hypothesis.expectedIfHealthy}
Actual observed outcome: ${actualOutcome.slice(0, 500)}

Does the actual outcome reveal a genuine issue, or match
healthy, expected behavior?

Respond with ONLY valid JSON:
{"revealsIssue": boolean, "reasoning": string}`;
  const raw = await askClaude(evalPrompt);
  const { revealsIssue, reasoning } = JSON.parse(raw);

  return { hypothesis, actualOutcome, revealsIssue, reasoning };
}

Example — A Real, Genuine Discovery

const hypothesis = await generateHypothesis(cartObservation,
  'Explore the checkout functionality and identify unexpected behaviour.');
// { description: "Applying the same discount code twice may
//   incorrectly stack the discount",
//   testSteps: ["Apply discount code SAVE10", "Apply SAVE10 again"],
//   expectedIfHealthy: "The second application is rejected with
//   a clear message; the discount is NOT applied twice" }

const result = await testHypothesis(hypothesis, page);
// { revealsIssue: true, reasoning: "The cart total reflects a
//   20% discount after applying the same 10% code twice — this
//   does NOT match the expected, healthy rejection behavior" }

Why It Matters

Nobody wrote a test case for "applying the same discount code twice" — Chapter 4's systematic generation, working from an explicit requirement, likely never would have either, since it's not an obvious negative case anyone would think to specify. This is exactly the kind of genuine, unplanned discovery exploratory testing exists to find.

Common Mistakes

  • Generating a vague hypothesis with no concrete test steps. "Something might be wrong with discounts" isn't testable — this page's structure requires a specific, executable hypothesis.
  • Skipping expectedIfHealthy and asking the model to judge the outcome without it. Without a stated healthy expectation, the evaluation has nothing concrete to compare against.

Best Practices

  • Always require a concrete, executable hypothesis with explicit healthy-case expectations before testing it.
  • Capture full evidence (Chapter 9's EvidenceBundle) for any hypothesis that reveals a genuine issue — this is exactly the kind of finding worth a complete, reviewable record.

Key Takeaways

  • A genuine hypothesis needs concrete, executable steps and a stated expectation for the healthy case — not just a vague area of concern.
  • Evaluating the actual outcome against the healthy expectation is what makes "reveals an issue" a real, checkable judgment rather than a guess.
  • This is exactly the kind of unplanned discovery — like discount codes stacking incorrectly — that systematic test generation from Chapter 4 would likely never surface on its own.
