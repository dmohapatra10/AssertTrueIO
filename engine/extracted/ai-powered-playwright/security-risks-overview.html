Introduction

How It Works — The Six Real Categories

PROMPT INJECTION — malicious CONTENT on a real page trying to
  hijack the AGENT'S behavior (GENUINELY new — Chapter 19'S own
  next page)

CREDENTIAL exposure — API keys, TEST account passwords, real
  secrets leaking into logs or PROMPTS (Chapter 8, Chapter 16,
  extended HERE)

EXCESSIVE permissions — an agent or TOOL granted more ACCESS
  than its actual task NEEDS (Chapter 15'S allowlists,
  extended HERE)

UNCONTAINED execution — an agent running with NO isolation
  from real, PRODUCTION systems (Chapter 13'S environment
  check, extended HERE)

UNSUPERVISED automation — a change REACHING production with
  NO human review (Chapter 11'S OWN core rule, extended HERE)

UNTRACEABLE actions — NO real record of WHAT an agent did,
  WHEN, or WHY (genuinely new — Chapter 19'S closing page)

Why It Matters — Autonomous Browsing Has a Real, Distinct Surface

A traditional Playwright script only ever does exactly what a human wrote — its risk surface is bounded by the code itself. Chapter 13 and 14's agents genuinely decide their own next action based on what they encounter, including content on real pages nobody wrote or reviewed. This is precisely what makes prompt injection a real, new risk category that a fixed script never faced.

Example — Mapping ShopSmart's Own Real Exposure

ShopSmart's exploratory agent from Chapter 13 browses real product pages, including user-submitted reviews. Every one of this page's six categories applies concretely here: a malicious review could attempt injection; the agent's API key needs real protection; its tool access should be scoped to what exploration genuinely needs; it should run isolated from ShopSmart's real production database; any code change it proposes needs human review; and every action it takes should be genuinely traceable afterward.

Common Mistakes

  • Treating these six categories as equally novel. Four of them extend real discipline this track already built; being clear about which is genuinely new (prompt injection, audit logging) versus consolidated (the rest) shapes how to read this chapter.
  • Assuming a simple, deterministic Playwright script needs the same security treatment as an autonomous agent. A script's risk surface is bounded by its own code — an agent's is not, which is exactly why this chapter exists specifically for AI-powered automation.
