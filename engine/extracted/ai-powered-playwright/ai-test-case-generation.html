Why Six Genuinely Different Categories

HAPPY PATH    — does it work when used CORRECTLY?
NEGATIVE      — does it FAIL correctly when used INCORRECTLY?
BOUNDARY      — does it hold at the EDGES of valid input?
EDGE CASE     — does it handle UNUSUAL, but VALID, combinations?
VALIDATION    — does it REJECT malformed input SAFELY?
SECURITY      — does it resist ADVERSARIAL-looking input SAFELY?

A human tester relying on intuition alone tends to over-represent happy path and under-represent the rest — not from carelessness, just because happy path is what comes to mind first. This chapter's real value is systematic, genuinely broad coverage across all six, not just faster happy-path tests.

Common Mistakes

  • Generating hundreds of scenarios and running every single one, always. This chapter's final pages are explicit that prioritization — deciding what's genuinely worth running, and when — matters as much as generation itself.
  • Treating "security test generation" as an invitation to build actual attack tooling. This chapter's scope is strictly about generating scenarios that confirm ShopSmart handles adversarial-looking input safely — the same kind of input validation testing any careful QA engineer already does by hand, just done more systematically.

Best Practices

  • Generate broadly across all six categories before deciding what to prioritize — narrowing too early can mean missing a category entirely.
  • Keep reusing Chapter 3's validation discipline — every generated scenario and every generated test still needs checking before it's trusted.

Key Takeaways

  • Thorough test generation means systematically covering six genuinely different categories, not just generating more happy-path tests faster.
  • This chapter extends Chapter 3's exact foundation — the same client, the same validation discipline — across more scenario types and more of ShopSmart's real features.
  • Generation and prioritization are two separate, both-necessary skills — this chapter covers both.
