Introduction

The previous page captured everything comprehensively — genuinely cheap to do. Sending everything to AI for every single failure is a different decision, with a real, ongoing cost this page addresses directly.

Why It Matters — Comprehensive Capture, Selective Sending

The PREVIOUS page's EvidenceBundle can include a FULL video
FILE, a MULTI-megabyte trace, and PAGES of console LOGS.

SENDING all of this, for EVERY failure, EVERY time:
  - Costs REAL money — Chapter 18 covers this in DEPTH
  - Adds REAL latency to EVERY analysis
  - Often adds NOISE, not SIGNAL — most console LOGS from a
    LOCATOR failure are COMPLETELY irrelevant to WHY it failed

Step-by-Step Implementation — Selecting Relevant Evidence

// src/select-evidence-for-analysis.ts
import { EvidenceBundle } from './capture-evidence';

export interface AnalysisPayload {
  errorMessage: string;
  relevantStackFrames: string;
  recentConsoleErrors: string[];
  recentNetworkFailures: string[];
}

export function selectEvidenceForAnalysis(
  bundle: EvidenceBundle
): AnalysisPayload {
  return {
    errorMessage: bundle.errorMessage,
    // Only the FIRST few frames — usually where the REAL
    // problem is; deep framework internals rarely help
    relevantStackFrames: bundle.stackTrace.split('\n').slice(0, 5).join('\n'),
    // Only the LAST few — most RECENT, most likely RELEVANT
    recentConsoleErrors: bundle.consoleLogs.slice(-5),
    recentNetworkFailures: bundle.networkFailures.slice(-5),
  };
}

Code Explanation

Notice screenshotPath, videoPath, and tracePath from the previous page's bundle don't appear here at all — they're binary or large files, genuinely different from text that can be pasted into a prompt. They're not discarded; they stay available as real artifacts a human (or, later in this tutorial, a vision-capable analysis step) can open directly, rather than being forced into a text prompt where they don't belong.

Example — Sending the Selected Payload

import { askClaude } from './ai-client';

async function analyzeFailure(payload: AnalysisPayload) {
  const prompt = `A Playwright test failed.

Error: ${payload.errorMessage}
Relevant stack frames: ${payload.relevantStackFrames}
Recent console errors: ${JSON.stringify(payload.recentConsoleErrors)}
Recent network failures: ${JSON.stringify(payload.recentNetworkFailures)}

Analyze this failure.`;

  return askClaude(prompt);
}

// A REAL, meaningfully smaller prompt than sending the ENTIRE
// bundle — genuinely faster, genuinely cheaper, and RARELY
// missing anything the FULL bundle would have added for a
// TYPICAL failure

Common Mistakes

  • Sending the full, unfiltered stack trace, console log, and network history every time. This page's whole point is that most of this is noise for a typical failure — a deliberate, small selection is usually just as useful, and consistently cheaper.
  • Assuming binary evidence like screenshots should be discarded since they can't be sent as text. They remain real, valuable artifacts for direct human review — being unsuitable for a text prompt doesn't make them worthless.

Best Practices

  • Select evidence deliberately for each analysis — recent, relevant entries rather than the complete, raw history.
  • Keep binary evidence (screenshots, video, trace) available as linked artifacts alongside the analysis, not forced into the text sent to the model.

Hands-On Exercise

Run selectEvidenceForAnalysis against a real evidence bundle from one of your own captured failures. Compare the resulting payload's size against the full bundle — and check by eye whether anything genuinely useful for understanding the failure got left out.

Key Takeaways

  • Comprehensive capture and selective sending are different decisions — Playwright makes the first cheap, but the second still needs deliberate judgment.
  • A well-chosen, smaller selection of evidence is usually just as useful as the full bundle, at meaningfully lower cost.
  • Binary evidence stays valuable as a directly-reviewable artifact, even when it doesn't belong in a text prompt.
