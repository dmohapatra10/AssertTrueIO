Why It Matters — Multiple Agents, One Shared Server

This is the real, concrete payoff of Chapter 15's own reusability argument — three genuinely different agents, built by three genuinely different teams, all calling the same MCP server's tools, each restricted by its own allowlist from Chapter 15's own security page. None of them needed to reimplement navigate or click_element; all of them share Chapter 5's real, original implementation underneath.

Example — Tracing One Real Request Through the Whole System

1. Checkout team's AGENT calls click_element via the shared
   MCP SERVER
2. The SERVER checks Chapter 15's ALLOWLIST — checkout'S agent
   IS authorized for this tool
3. Chapter 19'S browser CONTEXT restrictions apply — no camera,
   no DOWNLOADS, regardless of WHICH agent called it
4. The ACTION executes, gets logged to Chapter 19'S audit LOG
5. IF the action reveals a FAILURE, Chapter 9'S evidence
   capture RUNS, feeding Chapter 16'S CI quality GATE
6. IF a fix is PROPOSED, it lands in Chapter 11'S human
   approval QUEUE — NEVER auto-merged, regardless of WHICH
   agent or TEAM proposed it
