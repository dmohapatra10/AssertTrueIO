Introduction

This page builds the "AI Analysis" step from this chapter's architecture — given a broken locator and real information about the current page, ask the model to suggest what might have replaced it.

Step-by-Step Implementation

// src/suggest-locator.ts
import { Page } from '@playwright/test';
import { askClaude } from './ai-client';

export async function capturePageStructure(
  page: Page
): Promise<string> {
  const buttons = await page.getByRole('button').all();
  const buttonInfo = await Promise.all(
    buttons.map(async (b) => ({
      accessibleName: await b.getAttribute('aria-label') ?? await b.textContent(),
      testId: await b.getAttribute('data-testid'),
    }))
  );
  return JSON.stringify({ buttons: buttonInfo });
}

export async function suggestLocator(
  brokenLocatorDescription: string, page: Page
): Promise<string> {
  const structure = await capturePageStructure(page);

  const prompt = `A Playwright locator broke:
"${brokenLocatorDescription}"

Real, current page structure: ${structure}

Suggest ONE replacement locator, as a Playwright locator call
(like page.getByRole('button', { name: '...' })), using ONLY
elements that actually appear in the structure given above.

Respond with ONLY the locator call text, nothing else.`;

  return askClaude(prompt);
}

Code Explanation

capturePageStructure genuinely matters here — without it, the model would be suggesting a locator blind, working only from general patterns rather than what ShopSmart's page actually, currently contains. This is the same discipline Chapter 3's LOGIN_PAGE_STRUCTURE established, applied here to a page whose structure is being read live, not hardcoded.

Why It Matters — And Why This Alone Isn't Enough

This single suggestion is genuinely useful, and it's also exactly the kind of AI output Chapter 1 warned sounds equally confident whether right or wrong. One suggestion, accepted blindly, is still a real risk — this chapter's next two pages exist specifically to turn one guess into several genuine candidates, ranked and checked, rather than trusting this page's output alone.

Common Mistakes

  • Asking for a suggestion without capturing real page structure first. Without it, the model has no genuine, current information — it would fall back to general patterns, risking exactly the hallucination Chapter 1 described.
  • Treating this page's single suggestion as the final answer. It's the first step of a longer pipeline, not the whole solution — this chapter's next pages exist for a real reason.

Best Practices

  • Always capture real, current page structure before asking for a suggestion — never let the model reason from general training patterns alone.
  • Treat a single suggestion as a genuine starting point, not a trusted final answer — this chapter's remaining pages show why.
