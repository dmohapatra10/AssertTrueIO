Introduction

Human exploratory testing has always meant testing without a predetermined script — following curiosity and judgment about what's worth checking as you go. AI exploratory testing is the same idea, with an AI agent making those moment-to-moment judgment calls instead of a human tester.

How It Works — The Nine Real Steps

1. Understand the OBJECTIVE — "explore checkout, find UNEXPECTED
   behavior" is genuinely vague compared to Chapter 5's instructions
2. Identify RELEVANT pages — which parts of ShopSmart actually
   relate to checkout
3. Navigate
4. Interact
5. Observe
6. Generate HYPOTHESES — "what if I apply a discount code TWICE?"
7. Explore ADDITIONAL paths — following a hypothesis SOMEWHERE new
8. Capture EVIDENCE
9. Report POTENTIAL issues

Why It Matters — Steps 6 and 7 Are Genuinely New

Chapter 5's loop had steps 3 through 5 in some form — navigate, interact, observe, feeding into a next, already-known step. Steps 6 and 7 are genuinely new: generating a hypothesis worth testing, and choosing to explore it, are both decisions with no predetermined answer. This is exactly the open-endedness Chapter 13's opening page named as the real difference.

Example — A Concrete Walk Through ShopSmart's Checkout

STEP 1-2: "Explore checkout" → relevant pages are cart review,
  shipping, payment, confirmation

STEP 3-5: Navigate to cart review, observe a discount code
  field that WASN'T explicitly mentioned in the objective

STEP 6: Hypothesis — "what happens if I apply the SAME discount
  code twice?" — nobody TOLD the agent to try this; it noticed
  the field and GENERATED this question itself

STEP 7-9: Try it, OBSERVE the result (does it STACK
  incorrectly? reject CLEANLY? crash?), capture EVIDENCE,
  report what was FOUND

Common Mistakes

  • Treating exploratory testing as "run the agent and see what happens," with no real structure. The nine steps above are a genuine structure — open-ended doesn't mean unstructured.
  • Expecting exploratory testing to replace Chapter 4's systematic scenario generation. They're complementary — systematic generation covers known, planned scenarios thoroughly; exploration finds the ones nobody thought to plan for.

Best Practices

  • Keep the nine-step structure in mind as this chapter's remaining pages build toward it — each page covers a real, distinct part.
  • Think of exploration as complementing, not replacing, the systematic techniques from Chapters 4 and 5.

Hands-On Exercise

Spend fifteen minutes doing genuine, manual exploratory testing on a real feature of your own application — no script, just curiosity. Note any moment where you generated a hypothesis ("what if I try...") that wasn't part of any existing test plan. That's exactly the behavior this chapter's remaining pages build into an agent.

Key Takeaways

  • Exploratory testing means testing without a predetermined script, using judgment about what's worth checking as you go — AI-powered exploration applies this same idea with an agent making those calls.
  • Generating and following a genuine hypothesis is the real, new capability this chapter adds beyond Chapter 5's observation loop.
  • Exploration complements systematic testing rather than replacing it — each catches what the other genuinely misses.
