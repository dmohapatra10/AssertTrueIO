ObjectMapper Configuration

Beginner 5 min read

Prerequisites: Deserialization: Response to POJO

What is this?

Everything shown so far has relied on Jackson's or Gson's default behavior, occasionally overridden per-field with annotations like @JsonProperty. For a whole project, annotating every single field on every single POJO is repetitive and easy to get inconsistent. RestAssured lets you configure the underlying ObjectMapper (Jackson's central configuration object) once, globally, so every POJO in your project follows the same rules automatically.

Why it's important

A project-wide naming mismatch (your team writes Java in camelCase, the API uses snake_case everywhere) is exactly the kind of thing that shouldn't need per-field annotations scattered across every POJO — one global configuration line solves it for the whole codebase at once.

Global Naming Strategy — The Snake_Case Problem, Solved Once

ObjectMapper mapper = new ObjectMapper();
mapper.setPropertyNamingStrategy(PropertyNamingStrategies.SNAKE_CASE);

RestAssured.config = RestAssuredConfig.config().objectMapperConfig(
    new ObjectMapperConfig().jackson2ObjectMapperFactory((cls, charset) -> mapper)
);

With this configured once (typically in a shared base test class or setup method), every POJO in the project automatically serializes/deserializes using snake_case JSON keys — itemName maps to item_name everywhere, with zero @JsonProperty annotations needed anywhere. This is the project-wide alternative to the per-field annotation approach shown in the Serialization page.

Ignoring Unknown Fields (or Not)

ObjectMapper mapper = new ObjectMapper();
mapper.configure(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES, false); // default behavior — lenient
// or, to make it STRICT instead:
mapper.configure(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES, true);

The lenient default (silently ignoring fields your POJO doesn't define) is usually what you want — it means an API adding a new field doesn't break every existing test that deserializes its responses. The strict alternative is a deliberate choice for a narrower purpose: a contract test specifically designed to fail the moment the API's actual response shape changes in any way, catching an unannounced breaking change immediately rather than silently tolerating it.

Controlling Null Inclusion Globally

ObjectMapper mapper = new ObjectMapper();
mapper.setSerializationInclusion(JsonInclude.Include.NON_NULL);

Rather than annotating @JsonInclude(NON_NULL) on every field that might be null, this single line applies the same "omit nulls from output" rule project-wide — useful for APIs that consistently treat an omitted field differently from an explicitly-null one across their whole surface.

Real-World Example — A Shared Base Configuration Class

public class ApiTestConfig {

    public static void configureObjectMapper() {
        ObjectMapper mapper = new ObjectMapper();
        mapper.setPropertyNamingStrategy(PropertyNamingStrategies.SNAKE_CASE);
        mapper.configure(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES, false);

        RestAssured.config = RestAssuredConfig.config().objectMapperConfig(
            new ObjectMapperConfig().jackson2ObjectMapperFactory((cls, charset) -> mapper)
        );
    }
}

// In a shared base test class:
@BeforeAll
static void setup() {
    RestAssured.baseURI = "https://api.example.com";
    ApiTestConfig.configureObjectMapper();
}

This is the natural home for ObjectMapper configuration in a real project — set once, alongside the base URI configuration from Chapter 2, and every test in the project inherits consistent serialization/deserialization behavior without needing to think about it again.

❌ Fragile vs. ✅ Recommended

// ❌ @JsonProperty("item_name") repeated on every single field, across every single POJO,
// in a project where the ENTIRE API consistently uses snake_case
public class OrderRequest {
    @JsonProperty("item_name") private String itemName;
    @JsonProperty("quantity_ordered") private int quantityOrdered;
    // ...repeated across dozens of classes
}

// ✅ One global naming strategy, zero per-field annotations needed anywhere
mapper.setPropertyNamingStrategy(PropertyNamingStrategies.SNAKE_CASE);

Common Mistakes

  • Annotating every field individually for a naming convention that's actually consistent across the whole API — a global naming strategy solves this once instead of dozens of times.
  • Enabling strict unknown-field failure project-wide without a specific reason — turns routine, harmless API additions into widespread test breakage.
  • Configuring the ObjectMapper differently in different test classes instead of once in a shared base — produces inconsistent serialization behavior that's confusing to debug.

Edge Cases

  • An API that's mostly snake_case but has a few camelCase exceptions (a legacy endpoint, third-party integration) — combine a global naming strategy with per-field @JsonProperty overrides on the specific exceptions.
  • Different naming conventions across genuinely separate APIs in the same test project — use separate ObjectMapper configurations (and separate RequestSpecifications, covered in Chapter 8) per API rather than forcing one global config to serve both.

Debugging

If serialization/deserialization behaves unexpectedly after adding global ObjectMapper configuration, confirm it's actually being applied — check that RestAssured.config is set before any test runs, typically via a @BeforeAll in a shared base class, not scattered inconsistently across individual test files.

Best Practices

  • Configure the ObjectMapper once, globally, in a shared setup location — not per-test or per-class.
  • Default to lenient unknown-field handling; reserve strict mode specifically for deliberate contract tests.
  • Prefer a global naming strategy over scattered per-field annotations whenever a naming convention is genuinely consistent across the API.

Practice Exercise

Configure a global ObjectMapper with snake_case naming and lenient unknown-field handling, apply it in a shared base test class, and confirm a POJO with camelCase Java field names correctly serializes to and deserializes from snake_case JSON with zero per-field annotations.

Summary

Global ObjectMapper configuration — naming strategy, unknown-field handling, null inclusion — solves project-wide serialization conventions once, instead of requiring per-field annotations scattered across every POJO. Set it up once in a shared base test class alongside your base URI configuration, and every test in the project inherits consistent behavior automatically.
